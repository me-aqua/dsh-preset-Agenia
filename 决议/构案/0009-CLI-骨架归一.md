## ① 背景（现量）

20 支 CLI（`presets/agenia/bin/*.mjs` + `.tools/*.mjs`）各写一套入口骨架：

| 函数 | 定义数 | 实现种数 | 字符跨度 |
| --- | ---: | ---: | --- |
| `parseArgs` | 11 | **11** | 613–2,252 |
| `cliError` | 7 | **7** | 128–172 |
| `emit` | 7 | 3 | 83 / 105 / 485 |
| `main` | **13** | 13 | 入口各不同（组长初稿写 12 —— 漏了 `.tools/mount-dashboard-profile.mjs:419`，第 2 关量出来纠正） |

后果不是「代码长」，是**参数形式不统一**：`bug-20261113-19`（`--backup-dir=<dir>` 被静默忽略、回落默认目录）就是这族的一个实例 —— 11 套解析器、11 种对「未知参数」的态度。

## ② 决定

1. 新建 `presets/agenia/lib/cli-harness.mjs`，导出三个：`parseArgs`（**同时接受** `--k v` 与 `--k=v`；未知参数必须出声）、`cliError`（统一 `{code, message, details}`）、`emit`（一行 JSON）。
2. 11 支有 `parseArgs` 的 CLI 改为 import；`main` **不动**（每个入口本来不同）。
3. `tree-at-commit.mjs` 的 `parseArgs`（2,252 字符）单独核：若它的形状无法收敛（确实需要别的），进**同名允许清单**（有名 + 理由），本票不含它。

## ③ 复用什么

- `lib/cli-guards.mjs`（B3 立的模块形状：纯函数、无副作用、可被出厂件内联）
- B1/B3 的内联机制（若某支 CLI 是单文件出厂）
- `-19` 的教训直接当判据：**两种参数形式各一条腿 + 未知参数必须报码**

## ④ 不复用什么

- **否「保留各写一套、只加判据钉住它们一致」**：不一致正是今天的病。
- **否「一次把 20 支全改」**：先改 11 支有 `parseArgs` 的，每支单独可见；一次改完会让「谁坏了」不可定位。
- **否「把 `main` 也抽成模板」**：入口本来就各不相同，抽了只是把差异搬进参数表。

## ⑤ 新增什么

- `lib/cli-harness.mjs`（3 个导出）
- 每条 CLI 的参数腿：`--k v` / `--k=v` / 未知参数出声
- 一条判据：11 支 CLI 里 `function parseArgs` / `cliError` / `emit` 各 **0 定义**（`tree-at-commit` 若进允许清单则单独记）

## ⑥ 公共化时点

本票内完成：11 支 CLI 都 import 共享件；与 `-19` 同批闭合（那支票的修法就是这里的「未知参数出声」）。

## ⑧ 第 2 关定下的三条（2026-11-13）

1. **未知参数的码 = `E_ARG_USAGE`**（不用 `E_USAGE`）：`E_USAGE` 在三支 CLI 里已经是「不认识的 op」，复用它会让「参数写错」与「没这个 op」在读数上同形 —— 这正是我们一直在治的那族。没有既有判据断言 `E_USAGE` 用于未知参数，改动只是一条常量 + 契约 §5.2。
2. **`main` 是 13 个**（本票 §① 初稿写 12，漏了 `mount-dashboard-profile.mjs:419`）：判据钉 13，并在读数里记「构案说 12」的差异 ⇒ 以判据为准，本票已改。
3. **`bug-20261113-19` 不并入本票**：它住在 `mount-dashboard-profile.mjs` 的**内联参数处理**里（那支没有 `parseArgs`），而本票只覆盖 11 支有 `parseArgs` 的。⇒ `-19` 保留自己的票，但**修法必须用共享件的解析规则**（同一套「未知参数出声」），不许在那边再手写一段。

## ⑨ 第 3 关后组长裁定（2026-11-13）

**决定一：`tests/**` 这次不是零字节 —— 批准，但记成例外。**
第 3 关改了 **10 个** `tests/` 文件（第 3 关自报 8 个是漏算 —— 它自己那张表的最后一行写着 3 个文件；第 4 关用 `tree-at-b3r2` 与 `tree-at-b4` 两份副本逐份比出来）（块移动、沙箱注册表、适配器的 `cliError` 依赖、拷贝来的工具夹具）。它报得对：**我那张卡要求的三件事（tests 零字节 + RED 0 + 出厂件三块内联）本身不可能同时成立** —— 卡是我写错的，不是它违规。
⇒ 例外条件是：**只许动机器可读的注册表 / 夹具闭包 / 冻结散文，一条腿都不许增删或放宽**，且逐文件写「为什么非改不可」。
🔴 **实测：10 个文件里没有一条腿被增、删、放宽，用例数 218 与测试树 166 份都没变；但两条期望值确实迁移了** ——
- `PINNED_ERR_NAMES`：install / rollback 的 `InstallCliError` / `RollbackCliError` → `CliHarnessError`（一支 `cliError` ⇒ 一个类名）；
- `SHIPPED_HEADER_PARAGRAPH`：「两段」→「三段」+ ③ 两行（第三块内联）。
两条都是**诚实的后果**、钉子没有变弱（三格仍逐处字面钉；某支改回本地 `cliError` 会先被腿 ⑦ 抓）。**但它们违反了我原话「no case count or expectation changed」⇒ 我这句话是假的，已按第 4 关 r1 改正**；以本段为准，签：组长 2026-11-13。
⇒ 以后的卡：「`tests/**` 只在具名例外清单内可动，每项带理由」——不许再写「零字节」。

**决定二：`publish-staged` 扩面（3 支 bin → 7 支 bin + 整个 `lib/`）—— 批准，并且它暴露了一个更大的洞。**
它发现 staging 里 4 支被转换的 CLI 还是旧版、判据腿判的是**旧代码**；而 `F57-TARGET` 只比 `target-lag.json` 声明过的那一条，**看不见未声明的差异**。⇒ 已开票 `bug-20261113-23`：拷贝表从派生来 + 靶子对比必须报「未声明差异 N 处」+ 一条「staging 落后两处必红」的判据。
本票接受扩面后的现状（否则腿全在判旧代码），但**扩面本身不是本票的交付**：它的正确性由 `-23` 收。
