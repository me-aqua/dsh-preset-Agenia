## 背景

B1（构案 0006）把 `writeFileAtomic` 从 3 份并成 1 份。B1 的评审发现：**「原子写」这个概念还有三处手搓实现**，而按**名字**数的 census 数不到它们 ——

- `presets/agenia/lib/dashboard.mjs:174-182`（看板快照写盘）
- `presets/agenia/inject.js:1076-1078`（注入器，4,180 行单文件）
- `presets/agenia/inject.js:2794-2796`

而且 **`DASH-05`（`dash05-snapshot.test.mjs:476-495`）是按源码形状钉的** —— 把它们改成共享件会让一条本来该绿的判据变红：那不是判据在保护行为，是判据在锁实现。

## 决定

1. 三处改调共享件 `lib/atomic.mjs` 的 `writeFileAtomic`；`inject.js` 若因宿主 ESM 加载方式无法静态 import，则**内联同一份正文**（与 B1 对出厂 rollback 的处理同形），并在文件头注明来源。
2. **`DASH-05` 改成行为判**：断快照的**内容与形状**（键集/类型/可观测的原子性），不断「源码里有没有 `writeFileSync` + `renameSync`」。判据先改成行为判（允许它红），实现落地后转绿 —— 顺序不许反。
3. **census 加「按形状」的计数口径** `atomic-write-by-shape`（临时名写入 + `renameSync` 的模式，按处计），并配：阳性对照（手搓样本必须数出来）、阴性对照（只读/只 rename 必须 0）、有名有理由的 allowlist、以及「样本数 < 预期 ⇒ 红」的地板。

## 复用什么

- `lib/atomic.mjs` 的 `writeFileAtomic`（B1 刚归一的并集版本）与 `deletableVerdict`
- `.tools/census.mjs` 的 `COUNT_RULES` 机制（新口径按现有表格形状加，不另造一份）
- B1 的内联手法（`@inline-begin/@inline-end` 标记 + 发布时换头 + 断言）

## 不复用什么

- **否「保留三处手搓、只改 `DASH-05`」**：那只是让判据闭嘴，概念仍有三套实现，下次分叉没人看得见。
- **否「给 `inject.js` 直接静态 import 共享件」**：注入器由宿主加载且 ESM 按 URL 缓存，静态 import 可能把 `node:fs` 依赖拖进加载期；改内联。
- **否「`await import('../lib/atomic.mjs')` 绕过」**：B1 已否过同形（拿冻结约束的字面钻空子）。
- **否「用关键词正则当形状扫描」**：只认关键词会漏掉变形、又会被字符串误命中；要用「写入 + rename 同函数/相邻行」的结构特征，并带正负对照。

## 新增什么

- census 新计数口径一条（`atomic-write-by-shape`）+ 概念表一行
- `DASH-05` 的行为判版本（不是新增格，是改造；分母不变的理由写进契约）
- `inject.js` 内联源同源判据一条
