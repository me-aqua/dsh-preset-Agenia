# 构案 0010 · 评审删除优先

状态: 生效
主题: 评审删除优先
日期: 2026-11-13
拍板人: 老板
原话: 「我看现在的每票评审拿到的作业书好像没有特别强调『优先级：删除>修改>新增』，明智的开发者应该优先删掉一段代码而非修改一段代码，我希望评审每次的回答都偏向于『别改了，这个东西整个删掉，对当前代码功能实现没有任何影响』」
supersedes: —
superseded_by: —

## ① 背景（现量）

四份作业书 / 说明书里都有「宁缺毋滥」「代码质量」这一维，但**没有一条规定处置次序**。实测后果：
`bug-20261112-09`（闸没接派工路）的修法本来可以整段删掉「靠人记」的那部分，而第 2 关给的是「加一个命令 + 加一段说明书」；
本日的 B2/B3/B4 三票里，「抽共享件」取代了三次「删掉重复的那一份」的候选 —— 评审从没提过「整块删」这一支。

## ② 决定

优先级固定为 **删除 > 修改 > 新增**，写进四处（`team/review.md` · `job-briefs/technical-review.md` · `job-briefs/conversation-review.md` · `team/dev.md`）：

1. **评审第一问：这块该不该存在。** 删得掉就整删，判据是「删掉之后当前功能一行不变」；证据必须给到**调用方 / 可达性**（谁在用、哪条路会走到），不许用「看起来没人用」。
2. **给三种候选时，第一格必须是「整块删掉」那一支**；能整删的不许只写成「改成……」。
3. **每条发现带一格 `删除可行性`**：`可整删（证据：…）` / `删不掉（因为：…）`；填不出来的按「未验」记。

## ③ 复用什么

- 已有的「代码质量」维（`cand-20261104-0023`）与「宁缺毋滥」
- 已有的可达性证据口径（`cand-20261110-0330`：判功能可用先列前置条件与位置）
- 共享记忆里「同一族结构第二三个实例要描述符化、不许再拷一份」的结论 —— 删除优先是它的前置

## ④ 不复用什么

- **否「只加一句散文」**：散文没有可核对的面，评审可以照旧全提「改成……」。
- **否「加一格『建议删除』让评审自选」**：自选 = 不选；必须是**先答这一问**、答完才轮到改法。
- **否「让实现岗自行决定删不删」**：删除的影响面由评审给证据、由我（第 5 关）核，不由动手的人一句话决定。

## ⑤ 新增什么

- 四处的同一段文字（同一个措辞，不许各写一份）
- 每条发现的 `删除可行性` 一格
- 第 2 关三条腿：优先级行在 / 那一格在报告里出现 / 「整删」排在候选第一支（删任一条 ⇒ 红）

## ⑥ 公共化时点

本票内完成：四处文字落盘 + 判据三条腿 + 下一次技术评审按新格式交（首份作为样本）。
