# 现成做法

这份文件是**实例库**：`work-guidelines.md` 讲原则，这里给具体做法。
素材来自**之前做过的某个项目**的重构：一个原生 JS 版本被重写成了规范化工程。
下面每条都是那次实际落地的配置与做法，**照抄是安全的**。

> **2026-09-16 复查**：本文修正了三处与现状不符的地方 ——
> **体积阈值**（400/150 → 550/170）、**决定编号**（#47 → #50）、
> **pre-commit 的真实执行顺序**（原文的顺序与钩子里的「检查 1–16」不一致）。
> 写下的时候都是对的，是**项目往前走、文档留在原地**。
> 这正是 `work-guidelines.md` 第六条说的事：核对要带日期，过期要**当场改**。

## 一、检查体系怎么搭

**四层门禁，唯一原则是「按耗时分层」**：

| 层 | 时机 | 耗时 | 跑什么 |
| --- | --- | --- | --- |
| `pre-commit` | 每次提交 | ~2s | **16 项，按真实执行顺序**：密钥 → 调试残留 → 吞错误 → 一次性抽象 → 边界外防御校验 → 新源码必须带测试 → 体积 → 行尾/BOM/编码 → 语法 → ASCII → 标识符 → 提示词未内联 → 引擎不许解析模型输出 → ESLint → 相关单测 → **Prettier** |
| `pre-push` | 每次推送 | ~6s | 类型检查 → 全量单测 → 覆盖率门禁 → 构建 |
| `commit-msg` | 每次提交 | <1s | 约定式提交前缀 |
| CI | PR 与 push 到 main | 分钟级 | `npm run check` → 覆盖率 → 构建 → e2e 冒烟 → 组件故事 → 整页结构巡检 |

**为什么这么分**：pre-commit 每次提交都跑，必须秒级，所以只留**代码与文本层**；
浏览器那几层单机一次几十秒（e2e ~10s、stories ~19s、visual ~50s），
搬去 CI —— 不占开发者的等待时间，换台机器也照样跑。

**顺序本身也是设计**：

- **密钥排第一**：一旦提交就留在历史里，不可逆。
- **ESLint 与相关单测并行**（`Promise.all`），省一次串行等待。
- **pre-push 不提前退出**：四项全跑完再一起报，别让第二个失败盖住第一个。
- **会改文件的检查放最后**：格式化若排在前面并 `exit(1)`，**前面收集到的真正原因
  （例如密钥）永远打不出来**，只会看到"已格式化"。规则是：发现问题立刻报告并退出。

**一个命令串起来**（谁来都用这一条）：

```jsonc
"scripts": {
  "check":  "npm run typecheck && npm run lint && npm run format:check && npm test",
  "verify": "npm run check && npm run test:coverage && npm run e2e"
}
```

**跳过要留痕**：`SKIP_DISCIPLINE=1 git commit ...`，且**必须在提交信息里说明理由**。
注意连"跳过"这条分支也要跑与门禁无关的提醒（他的是"改了界面就去跑视觉检查"）——
提醒不是门禁，跳过门禁不等于不用看图。

**钩子靠 package.json 装，不靠自觉**：`"hooks": "git config --local core.hooksPath .githooks"`
挂在 `prepare` 上，`npm ci` 时自动生效。**构建也嵌了类型检查**：
`"build": "npm run typecheck && vite build"` —— 部署路径不可能绕过类型错误。

**这些检查他自己写脚本实现**，各管一件事，都放在 `.githooks/checks/`（共五个）：
密钥 `secrets.mjs`、语法 `syntax.mjs`、ASCII `ascii.mjs`、标识符 `identifiers.mjs`、
提示词 `prompts.mjs`。共同模式：**一文件一职责、命中即退出、放行规则精确到路径**。

| 脚本 | 查什么 | 实现要点 / 放行规则 |
| --- | --- | --- |
| `secrets.mjs` | 9 类已知 token 格式 | **只报位置与种类，绝不回显值**；跳过它自己（文件里就是规则） |
| `syntax.mjs` | 只报语法错误 | TS 编译器 API，亚秒级；`.vue` 只取 `<script>` 块；类型错误不归它管 |
| `ascii.mjs` | 代码骨架必须 ASCII | 扫「去注释、留字符串」的骨架；放行 `src/locales/`、`public/*.html`、`e2e/` + `*.stories.ts`、开发者工具目录 |
| `identifiers.mjs` | 标识符必须英文 | 扫「去注释**也去字符串**」的骨架 —— 中文文本不会误报，中文标识符也藏不到字符串里；对象字面量的键放行 |
| `prompts.mjs` | 提示词不许内联 | 判据是**长中文字符串字面量**（>30 字），不是猜关键词；留 `// allow: 理由` 逃生口 |

**为什么用「长度」而不是「关键词」判断提示词**：猜关键词既漏报又误报；
"长中文字符串"简单、确定，而且这个代码库本该一条都没有。

**另外几条 pre-commit 里值得抄的检查**（都不是通用工具，是自己写的）：

- **调试残留**：`debugger` / `.only(` / `TODO|FIXME|XXX` 一律拦下。
- **吞错误**：`catch` 块里既不抛也不返回、又没有注释，就算吞 ——
  ⚠️ 判据要**配对大括号**来隔离 catch 体，否则 catch 之后的一个 `return`
  会被误判成出口（实测发生过）。
- **一次性抽象**：在 composables/utils 这类目录里出现 `safeGet` / `withFallback` 之类的
  名字，就要求确认它真有两个以上调用点。
- **边界之外的防御性校验**：内部代码里出现 `typeof x === 'string'` 这类判断就拦，
  **放行清单是精确到文件的正则**（只有存档 / 卡 / 存储 / 配置 / LLM 这几个真边界）。
- **新增源码必须配测试**：每个 `src` 模块名都要在 `tests/` 的内容里出现，提不到就拒绝提交。
- **体积**：单文件 **550** 行 / 单函数 **170** 行 / 单次提交净增 **500** 行（生成物与文档豁免）。
  ⚠️ **阈值要跟着格式化器校准**：格式化会把模板属性拆行（一个组件 201 → 278 行），
  那是格式器的风格、不是代码膨胀 —— 但**要在提交信息里说明，别偷偷放宽**。
  最初是 400 / 150，2026-09-15 由**人拍板**调成 550 / 170，理由直接写进了钩子注释本身
  （「不拆，调上限并说明」）—— **改阈值本身也是一条要留痕的决定。**
- **引擎不许解析模型输出**：在大原则相关的目录里出现 `JSON.parse(` 就拦，报错直接点名
  那条决定和实测后果。

**三条「自己写检查」时最容易踩的坑（都实测过）**：

1. **静默失效的检查和通过的检查长得一模一样。** 有一次 `.js/.mjs` 不在 ASCII 检查的文件
   名单里，于是 pre-commit 每次把这些文件递给它、它却静默跳过 —— 直到有人全库跑一遍才发现。
   **所以：豁免清单与边界正则必须跟着目录结构走**，改目录时同步它们，否则规则会悄悄失效。
2. **检查代码要先剥注释、但必须保留偏移。** 把整块 `/* … */` 吃掉会让后面行号整体前移，
   报出来的位置是错的；`.vue` 里的 HTML 注释也要单独处理，否则 `-->` 里的 `--`
   会被后续扫描当成代码，甚至让一个 `/* */` 错误配对（实测报错行号偏了 12 行）。
3. **非 ASCII 检测器要在运行时构造。** 直接写字面量会踩 lint 的 `no-control-regex`；
   换成"ASCII 串 + indexOf"的取巧写法更糟 —— 多字符串上 `indexOf` 永远不为 0，
   于是每一行都被报成非 ASCII。

**报错输出必须显式解码**：

```js
const readOutput = (err) => {
  const decode = (v) => (Buffer.isBuffer(v) ? v.toString('utf8') : String(v ?? ''))
  return (decode(err.stdout) || decode(err.stderr) || decode(err.message)).trim()
}
```

`err.stdout` / `err.stderr` 是 **Buffer**，而**空 Buffer 为真** ——
`String(err.stdout || err.stderr)` 会挑中一个空 Buffer，把真正的内容吞掉
（"密钥扫描失败"曾以一条空记录的形式出现）。pre-push 也踩过同一个坑。

**重活要跑在 CI 上，但要诚实标注它的边界**：CI 是新的强制点，
可它**只有分支保护要求它通过时才真拦得住** —— 没有保护的分支照样能直推。
这一条被原样写在 CI 注释、pre-push 注释和 skill 里：**"现在仍可绕过，开不开保护是需要人拍板的取舍"**。

## 二、提交信息与版本

约定式提交，**这不是洁癖**——CHANGELOG 与语义化版本号都依赖它：

```
feat(card): 新游戏的第一帧由卡的开局决定（阶段 6a）
refactor(card): 卡格式 card/2 —— 顶层按「谁读」分三块，顺序只声明一次
chore(ci): 重型检查搬去 CI，本地钩子只留秒级门禁（阶段 8）
fix(e2e): 组件故事的「深色」截图其实全是浅色
```

`commitlint.config.js` 的做法（中文项目要改这几条）：

```js
export default {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'subject-case': [0],              // 标题用中文，英文的 subject-case 规则不适用
    'subject-full-stop': [2, 'never', '.'],
    'header-max-length': [2, 'always', 100],
    'body-max-line-length': [0],      // 中文的行长限制无意义
    'footer-max-line-length': [0],
  },
}
```

注意提交信息里带**阶段编号**（`阶段 6a`、`阶段 8`）——大改分阶段时，
一眼就能看出这次提交属于哪一步、还剩几步。

版本号：语义化 + 标签单独推送；**改了行为/修了 bug 才发版，只改文档直接提交**——
否则版本号会膨胀成 `v0.5.47`，用户反而看不出哪个版本重要。

## 三、代码规范怎么定

**ESLint 抓真 bug，Prettier 管排版，两者不越界。** 配置开头就写清定位：

> 只开「错了就是错了」的规则，不写「我更喜欢哪种写法」的规则。

**开类型感知 linting**（`projectService`），因为这几条"真 bug"规则需要类型信息：

```js
'@typescript-eslint/no-floating-promises': 'error',   // 忘了 await 的 Promise
'@typescript-eslint/no-misused-promises': 'error',    // 把 Promise 当同步用
'@typescript-eslint/no-explicit-any': 'error',        // 真正的 any 要出声
'preserve-caught-error': 'error',                     // 重抛要带 cause，否则丢上下文
```

**框架规则只留「会变成运行时 bug」的**：`vue/no-mutating-props` 开着，
而 `vue/attributes-order`、`vue/max-attributes-per-line`、`vue/html-self-closing`
一律关掉 —— **风格问题交给格式化器，不在 lint 里吵架**。

**豁免要写理由**，例如关掉全角空格检查：

```js
// ⚠️ 关掉 no-irregular-whitespace：中文排版里全角空格 U+3000 是故意的缩进
//    （例如叙事文本的首行缩进），不是脏字符。
'no-irregular-whitespace': 'off',
```

**类型配置要分 project，命令必须指到真配置**：根 `tsconfig.json` 是空壳聚合器
（`"files": []` + references），所以 `vue-tsc --noEmit` 不带 `-p` 等于**什么都没检查**
（实测：往里塞类型错误照样退出 0）。正确写法是 `vue-tsc --noEmit -p tsconfig.app.json`。
**声明"有类型检查"之前，先故意塞一个类型错误看它抓不抓得到。**

## 四、注释规范（写成了自定义 lint 规则）

**代码/变量/函数名全英文；注释全中文，只描述现在。**

```ts
/** 把毫秒差说成人话（1 年按 365 天折算） */
export function describeElapsed(ms: number): string {
```

- 函数上方一行说清**做什么**（不是怎么做）。
- `.vue` 的文件头注释写在 `<script setup>` **里面**，别写外面（看起来像 HTML 注释）。
- 行内注释只加在"代码看不出为什么"的地方：
  ```ts
  // ⚠️ 必须用 Object.hasOwn：写成 TOOLS[name] 时 constructor 会从原型链上取到真值
  ```

**禁止历史对比**——"原来的实现 / 旧版是 / 曾经 / 相比以前"。判据是**句式清单**
（正则列举十几种说法），不是语义判断。要说明约束，就写约束本身：

| 别写 | 写 |
| --- | --- |
| 原来用 innerHTML，现在改成模板插值，少了 XSS 隐患 | 全部走模板插值，由 Vue 自动转义，没有 innerHTML 拼接 |
| 之前这里忘了 triggerRef，界面不更新 | 整体替换也走容器属性：漏一处手动触发就是「界面不更新」这种查不出来的 bug |

**他为此写了自定义 ESLint 插件**（`tools/eslint-plugin-comment-style.js`），强制三件事：
具名函数必须有紧贴上方的注释、注释里不许有历史对比句式、`.vue` 文件头必须在
`<script setup>` 里。**豁免也要有理由**：一行写完的箭头函数、函数体 ≤3 行的小函数、
测试文件里的行内回调。**为什么做成 lint 而不是钩子脚本**：注释要跟着代码走，
lint 能在编辑器里实时提示。

**写这类插件踩过的三个坑（都是"实现细节选错 → 静默漏报"）**：

- 注释挂在**父节点**上（`export function` 的注释属于 ExportNamedDeclaration），
  只看函数本身会误报"没注释"；但**回退只能对 export 开** —— 对任意函数都回退，
  上一个函数的注释会顺带"喂饱"下一个（实测漏报）。
- 类方法的注释挂在 `MethodDefinition` 上，传 `node.value`（FunctionExpression）
  进去会变成"有注释也报缺少注释"。
- `.vue` 文件头必须按**文件行**判断，不能拿节点自己的行号当基准
  （Vue 的 Program 从 script 内容才开始），否则把正确写法也报出来。

## 五、测试怎么分层

**五层，各测各的，别串层**：

| 层 | 位置 | 环境 | 测什么 |
| --- | --- | --- | --- |
| 单元 | `tests/*.test.ts` | node | 纯逻辑与边界（默认 node，要 DOM 必须在文件头写 `// @vitest-environment jsdom`） |
| 组件 | `tests/components.test.ts` | jsdom | 渲染契约、点击后 emit 什么（**不测样式**） |
| 组件故事 | `*.stories.ts` + `e2e/stories.spec.ts` | Storybook + Playwright | 每个 props 状态在真浏览器里的渲染 |
| 功能冒烟 | `e2e/smoke.spec.ts` | Playwright | 玩家点得出来的路径（**测构建产物**，不是源码） |
| 视觉矩阵 | `e2e/visual.spec.ts` | Playwright | 状态 × 屏幕 + 少量像素基线 |

**边界靠机制钉住，不靠人记**：默认环境是 node、要 DOM 得显式声明；
冒烟测试由 `webServer` 强制先 `build` 再 `preview`，想测源码也测不到。

**门禁在哪**：单元/组件在提交时只跑**与暂存文件相关的**（`vitest related`，
推送时跑全量）；覆盖率与构建在推送时；浏览器那三层在 CI。

> 用 `vitest related <暂存文件>` 而不是 `--changed`：后者按工作区与 HEAD 的差异算，
> 会把**没暂存的**旁人改动一并算进来（实测多跑了 4 个文件）。
> 而且他诚实标注了局限：**"相关单测不是门禁，只是预警"** ——
> 没被任何测试引用的新模块由"新增源码必须配测试"拦，全量口径由 pre-push 兜底。

**假外部依赖按层各写一套**：

- 单元层：替换 `globalThis.fetch`，按调用次序消费预设回复，并**记录每次请求**
  （url / headers / body）供断言；句柄还能"下一次失败"、"先正常再交给回调"
  （用来造"第一步已改状态、第二步才挂"这种事务中途失败）。
- e2e 层：**`page.route` 拦 `**/chat/completions`**，不是注入脚本改 `window.fetch` ——
  注入那条路踩过"注册顺序错了就静默不生效"，而且没法按用例控制延迟与错误码。
  模式分 `narration` / `slow`（第一次拖 5 秒，看得见"正在生成"）/ `error`（上游 500）。

**假数据必须按真实协议给**：引擎走原生工具调用，所以假模型要回 `tool_calls`，
回"JSON 代码块"没用。**模拟得比真的宽松，是假通过的第一来源。**

**共享夹具**（一个 `tests/support/` 目录）：造一局的、造引擎上下文的、假 fetch 的、
语言派生模式的、最小卡的、整轮假回复的 —— **每个文件头第一句写清"为什么集中在这里"**。
夹具分「纯数据」与「带真存储」两档，测试按需要选。
判据：**同一个夹具在第二个文件里再写一遍时**才提取；fake 回复常量属于各用例的上下文，
硬合并只会让测试读不懂。另外"形状"一律从事实来源现取 —— 卡加一个节点，
假回复的顺序跟着变，不用手改。

**覆盖率门禁**（写在 `vitest.config.ts`，低于即失败）：

```
statements 99 / branches 94 / functions 100 / lines 99
```

- 数值是**实测后留余量**定的（实测 99.57 / 93.46 / 100 / 99.53），
  作用是拦住"加了功能没加测试"，不是刷满分。
- **统计范围显式列出**（游戏逻辑 + 引擎 + 工具 + store），Vue 组件由组件测试与 e2e 覆盖；
  ⚠️ **范围注释里写明"改了目录结构必须同步这里，漏改 = 搬出去的代码静默脱离门禁"**。
- **"新增功能必须新增测试"另有兜底**：`pre-commit` 检查每个 `src` 模块都在 `tests/`
  里被提到，提不到就拒绝提交。

**测试里最值钱的几条坑**：

1. **垫片没注册 = 全套静默假通过**：`setupFiles` 漏了一行，localStorage 垫片就没加载，
   存档相关断言**全部静默走"保存失败"分支，套件全绿但是假的**。
   垫片本身还要自检（Node 22+ 自带一个坏掉的原生 `localStorage`，值是 `undefined`，
   要探针试一次再 `defineProperty` 覆盖）。
2. **测试环境的 URL 也是配置**：jsdom 默认地址是 localhost，而产品在 localhost 上
   默认开调试模式 —— 测试要跑在别的域名上，才不会把那个默认值当成产品行为。
3. **语言是测试环境的一部分**：locale 钉在"参考语言"（中文，因为英文环境下**缺 key
   会退化成打印 key 名**，于是"缺 key"也能通过"不是中文"这类检查）；每个用例前重置，
   因为语言会跨用例泄漏。断言产品文案一律走 `t('key', {参数})`，不抄字面量。
4. **选元素用 `data-*` 钩子**，不按文案找 —— 文案随语言变。
   带参数的文案断言只看**前缀**，句子后半段改了不假红。
5. **模块级状态会跨用例**：每个用例开头重置；需要"换一份存储再重来"的走
   `vi.resetModules()` + 动态 import。
6. **断言写错会伪装成代码 bug**：先怀疑断言。写"兜底分支"的测试时，
   如果第二步回复没带工具块，循环会正常结束 —— 那条用例其实测的是正常路径。
   **要确认测试真的走到了目标分支**（数请求次数、断言对模型说了什么）。

## 六、UI 那一层：结构判据、像素基线、看图的习惯

**结构判据只有四条，写在一份 `probe.ts` 里，组件故事与整页矩阵共用**：

1. 横向溢出 `scrollWidth - innerWidth ≤ 1`
2. 元素伸出视口左右边界
3. 点按目标 < 24×24（**WCAG 2.5.8** 的最小尺寸，**并落实它的行内链接例外**，
   否则句子里的说明链接会误报）
4. **正文不许被悬浮控件压住**（按滚动容器裁剪后再判相交）

> ⚠️ 第 4 条**必须先按滚动容器裁剪**：滚出容器的部分在几何上仍有坐标，
> 不裁剪会把"正常滚出去的正文"全报成遮挡（第一次跑就报了 7 处假阳性）。
> 判据只写一份的理由很直白：**两份阈值必然走偏。**

**弱断言会骗过你**：位置类断言只判"元素在左半屏/右半屏"，拦不住"按钮跑到屏幕正中"
（旧布局也满足）。要判**贴边距离**（右边缘距视口右侧 < 40px）与**相邻关系**（间距 < 20px）。

**像素基线只给少数、稳定、人看过的画面**：

- **白名单 8 张**：中英 × 手机/笔记本、长故事、调试开、抽屉开、深色。
- **组件故事不建基线**：组件改动频繁，基线会变成天天刷新的噪音。
- 基线**进仓库**（约 650KB）、**文件名带平台后缀**：换平台要么重录、要么让 CI 跳过。
- **CI 只跑结构判据**（`--ignore-snapshots`），并把截图与两张总览页当工件上传
  —— 因为跨平台字体渲染必然不同，"直接比只会永远红"；
  而**基线是"人看过并认可"的锚点，重录必须有人当场看图**。
- 刷新要显式：`--update-snapshots`。⚠️ 有个坑：`reuseExistingServer` 会复用旧服务，
  `build` 不重跑 → 浏览器里是旧代码；而且**内容没变时快照文件根本不会被重写**
  （mtime/sha256 不变），于是你会以为刷新过了。

**视觉结果要可复现，就得把环境钉死**：禁动画、隐藏光标、`maxDiffPixelRatio` 给小值、
时区固定、语言固定、开 reduced-motion；**只对"有存档"的状态建基线**
（新开局取当前时间会抖）。

**一条真实的假通过**：「深色」那一半截图其实全是浅色（实测 32 对 PNG 逐字节相同）——
所以现在截图前先**断言主题类真的落到了 `<html>` 上**。同类做法：不能只看类名，
还要断言底色确实不同。

**最后一步不能省：看图。** 结构检查只保证"没溢出、没被压住、点得到"，
保证不了好不好看、够不够沉浸。所以巡检会生成两张总览页供人翻，
而且**提交时会按"你这次改了什么"给出对应的看图命令**（整页动过 → 跑整个矩阵；
只动组件 → 只跑那个组件的故事，并检查它到底有没有故事文件）。

## 七、真浏览器验证（这条最容易被跳过）

**HTTP 200 只说明文件送到了，不说明页面能跑。** 要在真浏览器里读运行时 DOM。

用 CDP，**不需要 puppeteer**——Node 自带 WebSocket 就够：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --user-data-dir=/tmp/cdp-x \
  --remote-debugging-port=9333 about:blank
```

然后 `fetch('http://127.0.0.1:9333/json/list')` 拿端点，连上后
`Page.navigate` → `Runtime.evaluate` 读 DOM。

**断言要落在运行时状态上**：组件是否挂载、交互后的 DOM、以及
**`Runtime.exceptionThrown` 与 4xx/5xx 必须为零**。**`--dump-dom` 不能用**：
它在脚本执行前就把 HTML 打出来，看到的是未挂载的模板，会误判成"框架没工作"。

三个会让你误判"页面是坏的"的坑：

| 现象 | 真实原因 |
| --- | --- |
| 读到的内容跟源文件一样，像没渲染 | 连到了启动时的 `about:blank` 标签页，必须显式 `Page.navigate` |
| 页面是 `chrome-error://chromewebdata/` | 导航失败，**先 curl 确认地址可达** |
| 脚本里 `import` 先于其他语句执行 | `import` 会被**静态提升** |

> ⚠️ 分工：**"读一下页面"用 CDP 就够；一旦要驱动交互（点击、输入、按用例控延迟与错误码），
> 就别手写协议了 —— 直接上 Playwright**，`chromium.launch()` 一行的事。
> （这条有真实翻车：为了驱动浏览器自己写了 CDP 客户端，花很久且很脆。）

**判断"浏览器还在不在"，别信进程枚举**：`curl .../json/list` 有响应 = 活着；
`Get-CimInstance` / 按名字枚举进程在沙箱里可能返回空 —— 会让人误判"窗口关了吧"，
而且**按进程名批量杀浏览器会杀掉用户自己开着的窗口**。

## 八、多平台协作：换行 / 编码 / 什么不进仓库

| 位置 | 要求 | 为什么 |
| --- | --- | --- |
| 仓库（索引） | 一律 **LF** | clone 到任何平台都一致 |
| 工作区：普通文本 | **LF** | Windows 编辑器默认写 CRLF，要拦 |
| 工作区：`.bat` / `.cmd` | **CRLF** | cmd.exe 用 LF 可能执行出错 |
| 所有文本 | 无 **BOM**、UTF-8 | BOM 多出三个字节；GBK 导致乱码 |

由 `.gitattributes` 声明、`pre-commit` 强制，并且**以 git 自己的结论为准**：

- **用 `git ls-files --eol` 看真相**，绝不手工数 —— `git add` 会做归一化，
  手工数看不到违规。`.gitattributes` 末尾直接写着"提交时由钩子强制检查，不靠自觉"。
- ⚠️ **别用 `git diff` 判断"文件有没有变"**：一个只改了换行符的文件归一化后与 HEAD
  完全相同，于是它不会出现在 `--cached` 里，钩子也就看不到它。
- 显式写 `eol=lf` 是为了**防假 diff**：不管开发者本机 `core.autocrlf` 设成什么，
  检出与提交都是 LF，不会出现"同一个人换个设置就整个文件都改了"。
- **大小写**：macOS 不敏感、Linux 敏感 —— 引资源时大小写必须与磁盘一致，
  否则本地过、线上 404。

**什么不进仓库：判据只有一条「能不能重建」。**
构建产物、覆盖率报告、截图工件、Storybook 产物、渲染出来的卡 md ……
都能从事实来源重新生成。
最有代表性的是卡：**渲染产物进了仓库，就多出一份要手动同步的"真相"**。

**还有一条少见的纪律**：**绝不自动格式化正在执行的钩子**。
钩子脚本没有扩展名，格式化器按 JS 猜；在提交中途改动钩子自身会让本次提交行为不可预测。

## 九、环境事实要写下来

把"这台机器/这个项目的既成事实"单独成文，**带日期和实测结论**：

- **版本上限由下游工具决定**，不能只看上游的 latest。实例：TypeScript 只能停在 6.x，
  因为 `vue-tsc` 还在 require TS 7 已不再导出的内部路径（7.0.2 报
  `ERR_PACKAGE_PATH_NOT_EXPORTED: './lib/tsc'`）—— 三个版本都真跑过才敢下结论。
- **平台特有的坑要写明**：Vite 8 默认只绑 IPv6（`curl 127.0.0.1` 返回 000，
  看起来像服务没起，配置里固定 `host` 即可）；部署在子目录时**开发地址也带 base 前缀**。
- **过时的文档要明确标注**："上游文档里遗留的 Windows 路径已过时，本机是 macOS，
  不要再照那套排查。" —— 留着不管比删掉更坏。
- 依赖装出来的东西（浏览器二进制等）不进仓库，**所以代码里不该出现绝对路径**。

## 十、文档结构

```
AGENTS.md              # 短入口：行为规则 + 两张地图（文档地图 / skill 地图）+ 快速入口
doc/DESIGN.md          # 当前设计：编号决定表（「决定 #50」）+ 每条决定的推导
doc/DESIGN-HISTORY.md  # 被取代的结论、提错过的记录、当年的备选方案
doc/CHANGELOG.md       # 由约定式提交驱动
.agents/skills/*.md    # 各领域操作手册：环境/检查/测试/UI 测试/验证/调试/发布/注释
prompts/<lang>/*.md    # 提示词真值（按语言分目录，构建期编进产物）
tools/                 # 自定义 lint 插件等自研工具
```

**入口文件要短**：`AGENTS.md` 只放"必须立刻知道"的，细节指向 skill ——
一上来塞几千行，读的人（和 agent）会直接跳过。**唯一可以越界的是"当前正在做的事"**，
那件事得让人一进门就知道。

**skill 怎么写**（每份都同一个模子）：

- frontmatter 固定三个字段：`name` / `description` / `whenToUse`
  —— 第三个就是"什么时候该加载我"。
- 正文：一张总表 → 分节 → **末尾"踩过的坑"**。
- 坑固定写成「现象 → 真实原因 → 修法」，每条带**实测结论**而不是警告口号。
- **什么配得上 skill**：跨任务复用的**领域操作知识**。
  不配的：一次性设计结论（进 DESIGN）、历史（进 HISTORY）、面向用户的说明（进 README）。
  好例子：素材版权那条规矩放"发布"skill 而不是设计文档 ——
  理由写在里面：「它是对外发布时才成立的检查项，放进设计文档会被推导淹没，
  也永远不会有人在发布时想起来」。

**设计决策怎么记**：**编号制**（#1–#50），每条三个字段 `决定 / 来源 / 理由`，
`来源` 区分"用户拍板"与"实施阶段定的"；短的进表，长的另起小节。
**被推翻的**：整段搬去 HISTORY，原处留一句「已被取代（日期，决定 #NN）」的指针；
HISTORY 顶部还有一张状态表逐条标 ✅/🔧/⏳。
**保留历史不是为了怀旧，理由写在开头：「决定会过时，来历不会」。**

## 十一、每条规则都带"怎么被强制的"

这是最值得学的一点：他写文档时**顺手写清这条规则由哪个检查兜底**。

| 规则 | 谁强制它 |
| --- | --- |
| 新增功能必须新增测试 | `pre-commit` 检查每个 `src` 模块在 `tests/` 里被提到 |
| 注释不写历史对比 | 自定义 lint 规则 `tavern/comment-style` |
| 文件头注释位置 | 同上 |
| 提交信息规范 | `commit-msg` 钩子（commitlint） |
| 代码里不许有中文 | `checks/ascii.mjs` |
| 标识符必须英文 | `checks/identifiers.mjs` |
| 提示词不许内联 | `checks/prompts.mjs` |
| 密钥不许进仓库 | `checks/secrets.mjs`（排在所有检查第一位） |
| 换行 / BOM / 编码 | `pre-commit` 用 `git ls-files --eol` 判 |
| 引擎不许解析模型输出 | `pre-commit` 扫 `JSON.parse`（放行两个既有边界） |
| 覆盖率不许掉 | `vitest.config.ts` 的 thresholds + pre-push |
| 结构不许溢出 / 被遮挡 | 一份 `probe.ts`，组件故事与整页矩阵共用 |
| "改完界面要看图" | pre-commit 的提醒（**不阻塞，但跳过门禁时也照打**） |

**写不出"怎么被强制"的规则，就是建议，不是纪律。** 要么给它加个检查，要么承认它只是偏好。
