# 决策账本（三册：产品 / 缺陷 / 构案）

> 这一份随预设分发给**所有工作区**。规矩住这里；账本数据住各工作区自己家里（`<工区>/账本/`）。

## 一、三册是什么

`账本/` 下住**三样地位同级的东西**：

```
账本/
├── 产品/   <NNNN>-<标题>.md   一条一文件（老板写的原话逐字）＋ INDEX.md ← 机器派生
├── 缺陷/   <YYYY-MM-DD>.json   每天一个文件、只追加的**事件流** ＋ INDEX.md ← 折叠出欠账
└── 构案/   <NNNN>-<标题>.md   一条一文件（我怎么落地）      ＋ INDEX.md ← 机器派生
```

- **产品**：老板发的。头 `层级: 产品` + `拍板人: 老板` + `原话:` 逐字；**不许有 `父`**。
- **构案**：技术层面的落地方式。头 `父:` 必填（产品号**或**缺陷 id），`依据P:` / `依据bug:` 两栏
  **至少一栏非空**，而且 `父` 必须出现在那两栏里（主父是来源列表的成员）。
- **缺陷**：一天一个 JSON 事件流，三个 kind —— `registered` / `assessed` / `disposed`；**只追加、永不改写**，
  一条票的现状是**折出来的**（`presets/agenia/lib/缺陷折叠.mjs` 是全仓唯一实现）。

## 二、两条硬规矩

1. **三张 `INDEX.md` 都是生成物**：只有 `node presets/agenia/bin/决议-check.mjs --op index` 会写它，
   手改当场红。改了实现 / 落了新条目之后重跑它。
2. **有 `.team/` 就必须有 `账本/`**：没有 ⇒ `LEDGER-NOT-INITIALISED`。
   新工区开局第一步：`node presets/agenia/bin/决议-check.mjs --root <工区> --op init` 建三册骨架。

## 三、三条链（机器可算，也是判据）

| 链 | 规矩 | 断了报什么 |
| --- | --- | --- |
| 产品 → 构案 | 每条**生效产品**至少一条生效构案在 `依据P` 里记着它 | `CHAIN-PRODUCT-NO-CHILD`（点名产品） |
| 缺陷 → 构案 | 每条**关上的缺陷**要么 `构案: NNNN`（且那条构案的 `依据bug` 反向记着它）、要么 `判假:`、要么 `历史:` | `CHAIN-BUG-NO-SCHEME` / `-DANGLING` / `-NOT-RECIPROCAL` |
| 构案 → 文件 | `presets/agenia/{bin,lib}/*.mjs`、`inject.js`、`team/*.md`、`job-briefs/*.md`、`说明.md` 每份都写 `依据: <构案号>`，**只许指生效构案** | `CHAIN-FILE-NO-BASIS` / `-BASIS-DANGLING` / `-BASIS-NOT-LIVE` |

`依据:` 的**具名豁免**只有四条（按文件给，不按目录给）：`now.md` · `log.md` · `账本/` 之下的东西 ·
`.team/**` 的卡片 / 报告 / 会话包 / 证据。

## 四、派工卡要写什么

卡首的结构化头块里（H1 → 空行 → 到第一个空行）：

| `票类:` | 还要写 | 判据 |
| --- | --- | --- |
| `构案` | `构案: <编号>` + `依据: <编号>` | 编号必须是**生效构案**；`依据` 必须出现在那条构案头的 `依据P` / `依据bug` 里 |
| `产品` | `产品: <编号>` | 编号必须是**生效产品** |
| `数据` | `构案: —` | 纯数据票的具名豁免（不扩不缩） |

别的词一律拒（fail-closed）—— 旧的 `新机制` 不再收。落卡走
`--op card-land --card=<路径> --day=<YYYY-MM-DD> --role=<test|dev|review|design>`：**先把卡逐字节落到
`.team/leader/<day>/cards/`，再在落下去的那一份上过闸**；被拒的卡照样在盘上（拒在哪一码要留得下来）。

## 五、缺陷怎么记（不自己决定修不修）

- 看见 bug ⇒ `node presets/agenia/bin/agenia-route.mjs --op bug-register` 记进 `.team/bug/ledger.json`
  （现象 / 证据 / 影响 / 复现）；**修不修由台账上的处置说**，发现的人不自己决定。
- 关一条缺陷要留链：`disposed` 事件里写 `构案: <构案号>`（那条构案的 `依据bug` 要反向记着它）、
  或 `判假: <为什么它不是缺陷>`。迁移进来的旧处置写 `历史: <原值>`（`check` 会印 `legacy_disposed` 条数）。

## 六、工具（都在预设里，任何工区都能跑）

```
node presets/agenia/bin/决议-check.mjs --root <工区>              # 判：三册 / 头 / 派生页 / 三条链
node presets/agenia/bin/决议-check.mjs --root <工区> --op init     # 建三册骨架（幂等，不覆盖）
node presets/agenia/bin/决议-check.mjs --root <工区> --op index    # 重写三张派生页（唯一写页的 op）
node presets/agenia/bin/决议-check.mjs --root <工区> --op fold     # 折叠缺陷册（只读）
node presets/agenia/bin/决议-check.mjs --root <工区> --op reconcile --archive=<旧台账>
node presets/agenia/bin/决议-check.mjs --op gate2-card --card=<卡>
node presets/agenia/bin/决议-check.mjs --op card-land --card=<卡> --day=<YYYY-MM-DD> --role=<角色>
node presets/agenia/bin/决议-check.mjs --op supersede <旧> --by <新>   # 只翻头块两个字段，正文不动
node presets/agenia/bin/census.mjs --root <工区> [--write-index]      # 概念 → 几处实现
```

退出码：`0` 无 problems · `1` 有 problems · `3` 用法或根不成立。
