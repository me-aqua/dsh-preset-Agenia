## 一、这一票要交什么

| 产物 | 落点（`<WS>` = 项目工作区根） | 说明 |
|---|---|---|
| 记忆复核报告 | `<WS>\.team\review\<日期>\记忆复核.md` | 人读：今天看到了什么、提了哪些维护案、哪些没提 |
| 维护案草稿 | `<WS>\.team\review\<日期>\maintenance\*.json` | 机读：一份一个文件，字段见下 |

**维护案的每一种**（都只是**草稿**，正式进共享池要组长 append-only 导入）：吸收 · 合并 · 退休 · 改类型 · 斩杀。
每一份草稿至少带齐三样：**基准快照版本**（`base_snapshot`）· **来源**（哪一次复核、哪个 `attempt`）·
**内容 SHA256**。组长会拿这三样与他的 fence 对，对不上他会拒收 —— 那不是你的事，你只管写全。

⚠️ **当天不生效**：你提的维护案由**次日**的记忆判决审批。所以别在报告里写"已经改了"。

## 二、必读输入清单（**只读这里点名的东西**）

`<DR>` = 任务书给你的 data root（绝对路径）。

| # | 输入 | 路径 | 读哪一版 | 核对什么 |
|---|---|---|---|---|
| 1 | 常识 | `<DR>\common-sense.md` | 任务书点名的那个 SHA256 | **必核 SHA256**：与共享状态里的 `common_sense_sha256` 逐字一致 |
| 2 | 快照 | `<DR>\memory\snapshots\<vN+1>.json` | **判决刚发布的那一版**（任务书点名）—— 不许自己挑 | `version` / `parent_version` / `totals` 与 `distribution` 严格相等 |
| 3 | 共享状态 | `<DR>\state\update\<day>.json` | 任务书点名的 `generation` | `phase` 必须是 `awaiting_review_start` 之后的态；`snapshot_available === true` 才动 |
| 4 | 路线 | `<WS>\.team\route\current.json` | —— | **本作业不读**（复核只看快照 + 常识 + 状态）；**更不许写** —— 写路线是组长的活 |

🔴 **缺任何一样、快照版本对不上、`snapshot_available` 还是 `false`、或者哈希对不上 ⇒ 当场停**：
不出半份草稿，把它当成「这一票没做成」报回去。**不许**拿"上一版快照"凑，也不许用别的 attempt 的输入。

⚠️ 除了这张清单点名的文件，别去读父会话历史或别的项目的东西。长会话压缩之后那些内容在不在、
对不对，**没有任何保证**。

## 三、提维护案要守的几条

- **斩杀类**：**只对输入快照 N 里 `is_double_low === true` 且 `double_low_streak >= 3` 的条目提**；
  用的是**快照里的已发布值**，**不许**拿"应用变更之后的临时份额"倒推"N 的时候它就够格"。
  没有冷却期、也没有数量上限 —— 别自己加。
- **改类型**：换类型会让 streak 清零、按新类型的半衰期与低线重算 —— 写清理由，别只写"更合适"。
- **吸收 / 合并 / 退休**：写清"并到哪一条 / 为什么现在退"，并给出**证据指针**（文件 + 行，或老板原话）。
- **普通候选（新增 / 修改）不归你**：那是所有岗位都能提的普通提案口；你只提上面那五类维护案。
- **旧 attempt 的候选**：照写、照报，**交给组长判**（他拒收或标无效）—— 别自己丢掉，也别假装它是这一轮的产物。
- **四类分布只是维护信号**：某类挤占、某类饿死可以提合并/重平衡，但**不是自动配额**，也不影响受理。

## 四、交活

报告里写清：**读的是哪一版快照** · **逐条维护案**（类型 + 目标条目 id + 理由 + 证据指针）·
**哪一条我判不了、需要什么才能判** · 草稿目录与各文件 SHA256。
判不了就写"判不了" —— 别拍脑袋，也别含糊过去。
