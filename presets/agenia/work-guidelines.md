# 全组须知

## 这一票在路线上的位置：目标 → 大阶段 → 任务 → 五关

路线是四层，从上往下 —— 越上面越慢变：

```
目标（这一票要做成什么）
└─ 大阶段（讨论 / 计划 / 执行一 / 执行二 / 脑暴 / 等你试用）
   └─ 任务（当前任务 0 或 1 个）
      └─ 五关（定形 → 契约与测试 → 实现 → 独立评审 → 验收）
```

⚠️ **五关挂在任务上，不是挂在大阶段上。** 说"第几关"的时候，前面得先有一个当前任务。
⚠️ **大阶段同一时刻只能有一个"当前"**（两个 current 是非法状态）；**当前任务可以是 0 个** ——
没有就是没有，不许凑一个出来。
⚠️ **摘要/看板的第一行永远是「目标 · 当前大阶段」** —— 别把大阶段名当成五关的值填进去。

**`now.md` 的第一行，永远是它被写下的那一天**，格式固定：

```md

```

日期放在最前面，是因为这一页的价值全押在"它还新不新"上：明天来的你会以为一切都还在原地，
而只有这行日期（和抽屉里那份 `log.md`）能让它自己说出"我是什么时候的"。
不带日期的 `now.md` 读起来和刚写的一模一样 —— 那是它唯一的危险。

**日期文件夹就是当天的工作抽屉。** 干完一天，抽屉合上不再打开。第二天开新抽屉，`now.md` 整个重写。

| **口径 · 推导 · 形态 · 决定的来历** | **`.team/`** —— 设计岗的日期抽屉放全文；组长 `memory.md` 留一句话 + 指针 | **她的工作区就是 `.team/`** |
| **只有"项目级、别人也要照着做"的决定** | **追加**到**项目自己本来就有**的那份设计档案（一条编号决定） | 那是**项目原有的档案**，协作者按它理解项目 |

⚠️ **项目原有的档案是哪一份，每个项目不一样 —— 先找出来再写，找不到就问老板，别自己造一份。**
⚠️ **本机环境与坑不写进项目设计**：那类事实归这台机器自己的档案，不归项目文档。

**仍然要问老板的**：需求方向本身（做什么 / 不做什么）· 影响对外承诺的取舍 · 他自己留着的事（推 `main` / 合并 / 强推）。

🔴 **不可逆的破坏性操作（覆盖 / 批量清除 / 回退到某个旧状态）—— 动手前后各落一次读数，写进当天 `log.md`：**

1. **动手前**：**目标是什么、它的语义是什么** —— "回到 X 之前"要落到**能指名道姓的那一份**。
2. **动手前**：**将要被抹掉的每一样**，逐条写"这是什么、要不要重做"。
   ⚠️ **已经在做的事，往往是先被抹掉的那一批** —— 别让"回退"顺手删掉已修好的东西。
3. **动手前**：当前未保存的改动有哪些 —— **覆盖和清除会连它们一起带走**。
4. **动手后**：关键文件的**语义**复核 —— 不是"文件在"，是"内容还是那个内容"。
5. **差额表**：**抹掉的每一样，逐条写"落在哪"** —— 落成一张票（带文件 + 要改的那一行），
   或者写清"为什么不落"。⚠️ **不许只记成 `now.md` 里的一行悬项**：
   `now.md` 是**每天重写**的短期页，它自己一停就没人看了。

⚠️ **项目有版本控制时额外一条**：不许用 `--force` 解决"本地看着不对" —— 远端是对的、强制推只会把对的东西推坏。

## 每日评审 · 会话包怎么"切"（**跨项目通用** —— 任何工作区第一次都会撞）

> 🔴 **这一节不是 Harness 专属。** 你在任何一个工作区、第一次要跑「会话评审」时，都会撞同一件事。
> 老板 2026-10-15 的原话：「**我其它工作区的会话第一次切也会遇到同样的问题，你得有个通用方案，让他们也知道咋做**」

### 问题长什么样

会话包的窗口 `from` = **路线里"最近一次评审完成"的时刻**（`<WS>/.team/route/current.json` 的 `reviews[]`）。
**那个文件不存在 ⇒ `from: null` ⇒ 包含你这条会话流的全部历史。**

⇒ 而"一天的对话"通常只是**一条流的一个片段**，可是**引擎的最小单位是整条流**：
窗口只能"**整条源排除**"，**不能裁剪单条流**（2026-10-15 实测：一条跨三天的流把 37 MB 旧账带进了"今天那份包"）。

⇒ 症状：**包巨大**（实测 68 MB）、**"昨天那份"里一半是前天的**、评审读不完。

### 三条处置 —— 按序走，前一条不成立才走后面

**① 先认是不是"第一次"**：`<WS>/.team/route/current.json` **不在** ⇒ 就是第一次。
⚠️ **还要先认一件事**：`route/current.json` 目前**没有写入者**（22 个 op 里没有一个写它）
⇒ **`from` 会永远是 `null`**，别指望它自己收窄。

**② 如果"那一天"那一段本来就全在"当天开的会话"里** ⇒ **照常打包**，`from: null` 也能对上。
（判据：那天要评的会话，`createdAt` 都落在那一天之内。）

**③ 如果那天用的是一条跨了天的会话** ⇒ **首次切只把"那天开的"会话放进 `sources`**，
并且 **在派工卡里明写**：*"首次切：源只含 A、B；C 没有进包"*。
🔴 **不许静默** —— 评审必须知道"它读到的不全"，否则它会把"没读到"当成"没发生"。

**④ 如果那天的话只存在于一条跨天会话里**（切不出干净的源） ⇒ **这一份如实缺**，开票等"按窗口裁剪单条流"。
🔴 **不许从大包里手工挑一段递给评审** —— 那是**喂加工过的证据**，"包里的话是证据"这条是铁的。

### 🔴 真正的解法：**引擎自己切分** —— 这是机器的活，不是人的纪律

> 老板 2026-10-15 当场否掉了我那个"每天开新会话"的提法，原话（逐字）：
> 「**那肯定不能每天开一个新会话，我哪怕口头答应你行动上也很难保证，你得自己去切分了**」

⇒ **「一条流 ≈ 一天」是机器的责任，不是老板的纪律。**
人不该为了工具的缺陷去改自己的习惯；**他要口头答应、行动上还记得** —— 那本来就不该是他的负担。

⇒ 所以上面 ①~④ 是**过渡期的临时处置**（能不做就不做，做了也要写明"源不全"）。
**真正的解是下面这条，而且它是"必须做"，不是"可选"**：

`session-packet` 要支持「**按窗口裁剪单条流**」：**窗口内的帧进包，窗口外的帧不进**。
（现在的实现只能"整条源收"或"整条源丢" —— 于是一条跨三天的流会把三天全塞进"今天那份包"。）

⚠️ 定形状之前先确认一件事：**帧 ≈ 事件**（实测 fixture `frames.count=4` 对应四个事件）。
⇒ "按窗口裁剪"落到实现上就是"**逐帧解、只留窗口内那几帧**"，
代价是**要解压整条流**（实测 68 MB 流 7.3 秒，可以接受），
但**它跟"先分类、后解压"那条纪律不冲突**：被整条排除的源照旧一个字节都不解。

### 还欠的两张票（任何工作区都会欠）

1. `session-packet` 要支持**按窗口裁剪单条流**（现在只能整条收 / 整条丢）—— 那是**改冻结口径**，要走评审通道
2. `route/current.json` 该由谁写、什么时候写 —— 现在没人负责，所以"上次评审之后"这个语义**从没启动过**

## 长期记忆的"分布"（`distribution`）

长期记忆（共享脑）**只有总量硬限：200 条且 60,000 字符**，四类**不各设硬帽**。
四类是 `general`（底层通用）· `boss`（关于老板）· `machine`（关于本机）· `project`（关于某个项目）。

- **记忆更新报告与每日状态要给出四类各自的条数与字符数** —— 那个字段叫 `distribution`，
  **恰好 4 项**；**0 条的类型也要留在里面**（不许因为它空就省掉一行）。
- 字符口径：**Unicode code point**（去 BOM · LF 归一 · 只数条目正文）。
- **偏科不是错**：某类挤占、某类饿死是**记忆复核的结构维护信号**（可以提合并 / 重平衡维护案），
  但**分布不参与自动配额** —— 没有"每类上限"这种字段。

> 🔴 **架构口径（老板 2026-10-16 拍，逐字）**：
> 「**可以冻结，新的你提案成新候选明天处理不就行了，少两条也无所谓，旧 memory 的参考价值也没有那么大，
> 反正随着以后的工作，我们会产生大量新提案的，现在的 memory 只是一个静态版本，
> 我的架构的价值就在于动态更新，降低一个静态版本的重要性**」
>
> **落成三条（以后每次取舍都照这个判）**：
> ① **旧本子（`.team/memory.md` 三卷 + 各岗位 `memory.md`）是"静态快照"，不是权威** ——
>    它**可以冻结**；搬漏的条目**不作废、走提案补**，不必因为它不完美就卡住整体。
> ② **对账的作用是"体检单"，不是"闸门"** —— 它报出"哪些可能漏了"，
>    **但不必等到 100% 才放行**（漏的 ⇒ 组长提 `proposal` ⇒ **次日判决**处理）。
> ③ 🎯 **真正承重的是「提案 → 判决」这条动态链**，不是任何一版静态快照。
>    ⇒ **判据**：**这件事能不能靠"以后提个案"解决？能 ⇒ 别为它卡住整体。**
>
> ⚠️ **但有一条顺序不许反**：**冻结的前提是"新库真的读得到"** ——
> 旧本子冻结的那一刻，**组员和组长就再也读不到它**；新库必须先真的进得了上下文，**中间不许有真空**。
