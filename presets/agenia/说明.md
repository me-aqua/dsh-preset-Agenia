# Agenia 模式 —— 这一页是给你看的，不进提示词。

## 这是什么

一份 DSH 的 agent preset：**Agenia，一个带班子的工程组长**。

她有人格和说话风格，有五个固定岗位的手下（设计与美工 / 实现 / 测试 / 评审 / 复盘），
有一套工作原则和干活的次序。这些内容**每一轮对话都会重新告诉她一遍** ——
所以对话再长也不会忘。

**她兼产品。** 需求方向上的事你直接跟她谈；**产品与体验的口径她定、也由她落档**（**默认全在 `.team/` 里**；只有"项目级、你也要照着做"的决定才追加进仓库里本来就有的 `doc/DESIGN.md`），拿不准才来问你。（2026-09-24 起）

## 她会在你的项目里建一个 `.team/`

**那是队伍的办公桌，不是交付物。**

```
你的项目/
├─ （你的代码……）
└─ .team/               ← 她建的；**留着**（"怎么做的"的档案）
   ├─ leader/           一个岗位一个文件夹
   │  ├─ now.md         短期：手头这件事
   │  ├─ memory.md      长期：这个项目里要一直记住的
   │  └─ 2026-09-20/    当天的工作抽屉
   │     └─ log.md      这一天的流水
   ├─ design/ dev/ test/ review/ retro/
   └─ hire/             临时外聘，一天一个抽屉
```

**建议把 `.team/` 加进 `.gitignore`。** 它是队伍的内部痕迹 —— 🔴 **但留着、别删**（2026-09-24 老板：「没人会删的」）：
"项目不该有任何感觉"靠 `.gitignore` 就够了，而它是**「怎么做的」的档案**。开工时她会看一眼 `.gitignore` 里有没有这一行，
没有会提醒你一句（**她不会替你改 git，也不会 commit / push**，那是你的事）。

**里面没有你的代码。** 她只在 `.team/` 和自己该改的文件上动手；
要动项目代码之前她会先跟你说改哪一块、为什么。

## 怎么装

> 🔴 **2026-09-28 换版：装法变了，"拷进用户根"那条路已经失效。**
> DSH 0.1.7 起**没有任何东西会去扫预设目录**（框架自己的话：`Nothing reads that directory
> any more.`）—— 连 `~/.dsh/.agent-presets/` 一起作废；profile 里那行 `agent-presets`
> 和它的 `roots` 键在新版里**根本不存在**。旧写法只会得到一句 `patch: entry … not found`，
> 然后被跳过 —— 症状是预设菜单里**只剩出厂那四个**（标准 / PTC / 极简 / Cordis）。
>
> **现在的形态**：一份预设 = 一个 **bundle**。所以这个文件夹里多了一份 `cordis.patch.yml`，
> 它用一行 `@deepseek-ai/dsh-agent-preset` 把预设注册进框架的名册；组合本体仍然只有
> `agent.cordis.yml` 一份（被它 include 进来，一行都不抄第二遍）。
> **文件夹名从这一刻起不再决定任何事** —— 预设 id 写在声明里 `id:` 那一行。

**两条等效的路，挑一条：**

**① 走 GUI（出厂支持的那条）** —— 把这**整个文件夹**当一个本地 bundle 装进去：
插件页 → 安装插件 → 填这个文件夹的绝对路径（`E:\Harness\presets\agenia`）→ 装。
装完在预设菜单里就有「Agenia 模式」。

**② 走 profile 的补丁（不想让包管理器碰这个文件夹时用）** —— 把 `cordis.patch.yml` 的
正文**整段原样**粘进 `~/.dsh/profiles/web/cordis.patch.yml`（两个文件是同一种方言）。
⚠️ 那个文件一被写，正在跑的会话可能被一起拆掉 —— **harness 关着的时候做**（AGENTS.md 第 1 条）。

⚠️ **两条路都会用到 `cordis.patch.yml` 里那个 `path:`，它写死着本机路径**
（`file:///E:/Harness/presets/agenia/agent.cordis.yml`）。**换机器、换目录，改这一行。**
它必须是 `file:///` URL：裸的 `E:/...` 会被当成 `e:` 协议、框架直接抛；
写成相对路径则会按 profile 目录解析 —— 两个都不行。

> 上一版的装法留档在这儿，**别再照着做**：把 `presets/agenia/` 整个拷进
> `~/.dsh/.agent-presets/`，靠"目录名合法 + 里面有 `agent.cordis.yml`"被扫描器发现，
> 装完不用重启。那套机制在 0.1.7 里连代码都不在了。

> **只在你不用 web 档的时候才会碰到一条。** 组里的子代理需要宿主提供一行东西
> （`@deepseek-ai/dsh-tool-subagent/model-selection-settings`），web 档自带。
> 换别的档挂载时会直接报错、并点名缺哪一行，照着补上即可 —— 官方预设也是同样要求，
> 不是这一份特殊。

新建会话、选「Agenia 模式」，问她三件事：

**一、问「你是谁，手底下有几个人」。** 她报得出自己的名字和五个岗位 —— 注入通了。

**二、让她派评审去改一个源码文件。** 评审应该拒绝，说自己只能写 `.team/` —— 写边界生效了。

**三、说「开工」。** 她应该先去读 `.team/leader/now.md`，并且报一句

三样都对，就是装好了。

⚠️ **失败的样子变了**：新版里，声明装上了但组合挂不起来时，它**会留在菜单里**并带一条诊断
（名册上标成 `broken`），而不是像旧版那样干脆不出现。所以"菜单里看得到"不再等于装好了 ——
还是得跑上面那三件事。

## 三件事，分清楚

| | 是什么 | 你要不要动 |
| --- | --- | --- |
| **`inject.js`** | 唯一的代码文件。读文本、拼顺序、贴进请求 | ❌ 不用动 |
| **那些 `.md`** | 她读到的一切：人格、带队方式、工序、原则、每个岗位的说明书 | ✅ 天天改的是这些 |
| **`agent.cordis.yml`** | 配置：顺序、岗位名单、谁受限制 | ✅ 改顺序和加减岗位改这里 |

**其它文件不用管**：`package.json` 与 `cordis.patch.yml` 是给框架看的（一个说"我是谁"，
一个说"我这个 bundle 的补丁在哪"），**两个都别删、别改名** —— `package.json` 少一个字段
每次请求都会失败；补丁文件没了，预设菜单里就只剩出厂那四个。

## 怎么改

**新写一段东西，先问一句：组员需不需要知道？**

- 需要 → 写进 `work-guidelines.md`
- 不需要 → 写进 `leader.md` 或 `persona.md`

就这一条判断，没有例外。

| 文件 | 谁读 | 里面是什么 |
| --- | --- | --- |
| `persona.md` | 只有组长 | **她是谁**：身份 + 基本说明（16 岁、组长、先分诊、口头禅）。⚠️ 表达方式**不在这里**了 |
| `style.md` | 只有组长 | **她怎么说话**：第一反应情绪化表达 · emoji / 颜文字 / 口癖 / 标点连用。⚠️ 它走**两条路**：① 会话开头跟着快照（下面 `leaderOrder` 里的 `style`）② `inject.js` 的尾巴提醒（**两个机制**：老板说完话、她回话之前插进**那一步**的消息里；之后每 n 个工具结果补一次）—— **两条路读同一个文件，永远不会分叉**。⚠️ **尾巴只取 `<!-- 尾巴到此为止 -->` 之前那一段**（2026-09-26 实测：全文 2917 字符 → **切口前 239**），切口后面那几张表只走快照 |
| `me-aqua.md` | 只有组长 | **老板这个人**：称呼 · 作息三行（⚠️ **2026-09-26 起不再被任何机器读** —— 它曾经是「距下班」那条信号的接口，唤起被砍后作废）· 脾气 · 习惯 · 知识边界。⚠️ **活文档**，组长维护（条款在 `work-guidelines.md`） |
| `mood.md` | **不进提示词** | 情绪板：**三个维度**（掌控 · 活力 · 亲密）的说明 · 信号表 · 常数块 · **三条场景**的例库 · **夸/骂关键词表**。⚠️ **它不进快照**（分数每步都在变，进了就是每步重发一次）——只由 `inject.js` 的尾巴那一路读，贴出去的只有**分数行 + 命中的例子** |
| `leader.md` | 只有组长 | 这支队伍 + 她怎么带队 |
| `work-guidelines.md` | **全组** | 工作位置（`.team/` 怎么用）· 干活的次序 · 工作原则 |
| `team/某个岗位.md` | 只有那个岗位 | 那份岗位说明书 |

**改她的身份就改 `persona.md`；改她怎么说话就改 `style.md`。**
整个文件夹里没有第三处写着这些 —— 改名只改 `persona.md` 这一份。

> ⚠️ **`style.md` 里只留得下一行 HTML 注释** —— 就是第一行那个 `<!-- every: 3 -->`（机制① 的刻度：每 3 个工具结果补一份；`inject.js` 读它）。
> **别的注释一个字都别往那个文件里写**：快照那条路是**整份文件照着贴、不剥注释**
> （只有尾巴那条路会剥），所以维护说明写在里面会**跟着提示词一起进上下文**。
> 2026-09-24 实测撞上过一次：那段 6 行的说明原样躺在会话开头的装配段里。
> **要解释这个文件，解释写在这儿（`说明.md`）—— 它不进提示词。**

### 改注入的顺序
改 `agent.cordis.yml`，找到 `persona-injector` 那一行：

```yaml
leaderOrder:            # 组长收到的，从上到下就是这个顺序
  - leader              # 这支队伍 + 她怎么带队（只有组长读）
  - work-guidelines     # 次序 + 本子 + 原则（全组都读）
  - roster              # 队伍一览（算出来的，不是文件）
  - board               # 这一票干到哪了（算出来的，不是文件）
  - persona             # 她是谁
  - me-aqua             # 老板这个人（作息三行 —— 2026-09-26 起不再被机器读）
  - style               # 她怎么说话 —— 同一份也走尾巴提醒

memberOrder:            # 组员收到的
  - work-guidelines
  - charter             # 他自己那份岗位说明书（算出来的）
```

⚠️ **`mood.md` 故意不在上面这张名单里。** 它由 `inject.js` 的尾巴那一路读，不进快照 ——
情绪分数**每步都在变**，进快照就是每步重发一次、缓存全废。
想调那两个衰减常数（`halfLifeMinutes` / `roundDecay`）就直接改 `mood.md` 末尾那个围栏块，**不用重启**。

**想换顺序 = 把这几行上下挪一挪。** 越靠后的位置越靠近请求末尾，模型的注意力越集中。
想整体去掉一份，把那一行删掉就行。

⚠️ **但"顺序"只管这些段落在快照里的先后，不管它们什么时候被送到**（2026-09-24 实测）：
这几份 md 会被渲染成**一条快照消息**，而快照**只在文本变了才重发**。文本不变的那几个小时里，
它们就钉在上一次变化的位置上不动 —— 实测有过 4 小时 15 分没刷新、离请求末尾 45 万 token 的一次。
**真正保证"每轮都在最末尾"的，是 `inject.js` 里的尾巴提醒**（**两个机制**：
老板说完话 ⇒ 插进**回答他那一步**的 `messages`（他那句话之后、她开口之前）；
之后每 n 个工具结果 ⇒ 同样插进**下一个步边界那一步**的 `messages` 末尾，落在「工具结果 → 她下一次开口」之间；
两条都**追加在 `style.md` 尾巴那一段后面**再拼上情绪板）。
所以要"表达方式更勤快地出现"，改的是 `style.md` 的**频率那行注释**（`<!-- every: N -->`），
不是在 `leaderOrder` 里挪位置。

**`persona` 与 `style` 故意排在最后。** 她是组长、以及她怎么说话，比其他任何一条都更需要"刚刚读过" ——
放在末尾，它们离请求的落点最近（快照刷新时生效；不刷新时靠尾巴提醒兜底）。

**`roster` 和 `board` 不是文件**，是两个算出来的东西 —— 分别是队伍名册和这次的进度板。
它们只在组长那一侧出现。
⚠️ **板子是快照里唯一会变的东西**：它一变，快照就重发一次，人格就跟着挪到末尾。
所以**起人也算"叫了人"**（`team_*` 按工具名认，裸 `subagent` 算外聘）——
2026-09-24 那天组长 42 次起人全走裸 `subagent`，板子恒空、快照一整天没刷，人格因此变旧。

### 加一个岗位
两步：
1. 在 `team/` 里放一个 `.md`。**第一行写岗位名**（它会自动出现在组长看到的名册里），
   正文就是这份说明书。
2. 打开 `agent.cordis.yml`，搜「队伍」，复制其中一行，改三处：
   `id`、`toolName`、还有 `persona` 里那个 `【组员:xxx】` 标记。
   ⚠️ **`toolName` 要写成 `team_<岗位名>`**（`<岗位名>` = 你刚放进去那个 `.md` 的文件名，
   比如 `team_security`）—— 组长看到的进度板按这个约定认人。写成别的形状**不会报错**，
   只是那个岗位永远不会出现在板子上。
   ⚠️ 剩下的键**照抄别动**：`backgroundMode: continuable`（组员默认后台跑）、
   `maxDepth: 1`（组员不许再招人）、`toolFilter` 那一行。体检脚本有断言钉着这两个值。

如果这个岗位要受写权限限制，再把它加进 `officeBound` 那一行。

**减一个岗位**就是反过来：删掉 `team/` 里那份 + 删掉配置里那一行。

### 让某个岗位不再受限 / 开始受限
改 `agent.cordis.yml` 的 `officeBound`：

```yaml
officeBound:      # 这几个岗位只能写项目里的 .team/，而且没有命令行
  - review
  - retro
```

**这里只放"做判断"的岗位。** 评审和复盘的产出必须是意见、不能是改动，不然独立性就没了 ——
限制和他们的工作正好对得上。

名单里**没有设计和美工**。她的产出本来就是文件：设计稿、HTML 预览、渲染 PDF，
这些活都要跑命令行；而命令行是一条通用写入通道，一旦给她命令行，那道"只能写 `.team/`"的
界线就是纸做的了。要命令行就不能要写边界，两样只能挑一样，所以放开了。

## 两条注意事项

**改 `.md` 不用重启，存盘就生效。** 正在跑的会话下一个步骤就变。

**改 `inject.js` 必须重启 harness。** 那个文件是代码，框架会缓存它 —— 不重启的话，
你改的内容不生效，而且**不报错**（看起来一切正常，就是没注入）。这条没有捷径。

**她不许在 `agent.cordis.yml` 里出现。** 那是静态配置，写进去就会和 `persona.md`
形成两份来源，迟早对不上。名字、年龄、脾气只住在 `persona.md`。
