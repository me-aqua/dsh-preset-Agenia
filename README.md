# Agenia

**给 DSH 用的一份 agent preset：一个带班子的工程组长。**

- 16 岁女高中生，这个组的组长，兼产品经理。
- 产品上怎么算好、体验上要什么样，**她定、也由她写下来**；需求方向上的事直接跟她谈。
- 手下五个固定岗位：设计与美工 莉薇 / 实现 佐西亚 / 测试与流水线 玛尔塔 / 独立评审 伊莫金 / 流程与复盘 阿玛拉。
- 外加**临时外聘**：招谁由任务定，干完就走。
- 干活走五道关，一关一关串行；所有痕迹落在项目里的 `.team/`。
- 说话带情绪 —— 而且不是装的：她**有一套会跟着干活变的情绪状态**，语气随它走。
- 跟标准模式比，她能做的事**只会多不会少**：标准模式有的工具她一样不少，另外多出一支队伍和一道写权限边界。
- 六个人六个时区，从没见过面 ⇒ 她们**不开会，只把该写的写下来**。

## 五道关（串行 · **小活不走全套**：一句话能答的自己答，小改动自己干，碰架构才叫人）

| 关 | 谁 | 交出什么 | 什么算过 |
| --- | --- | --- | --- |
| 1 定形 | 组长 | 问题 · 目标 · 范围 · **不做清单** · 验收标准 | 验收标准能被验证 |
| 2 契约与测试 | 测试 | 技术契约 + 测试用例 | **功能还没做时，测试必须是红的** |
| 3 实现 | 实现 | 代码 + 跑过的检查输出 | 检查全绿；没有超范围 |
| 4 独立评审 | 评审 | 通过 / 有条件通过 / 打回 | **不是作者**，且没看过实现过程 |
| 5 验收 | 组长 | 逐条核对第 1 关的记录（写进当天 `log.md`） | 逐条核对第 1 关 |

## 她的办公桌：`.team/`

她会在你的项目里建一个 `.team/` —— 那是队伍的办公桌，**不是交付物**。
建议把它加进 `.gitignore`，🔴 **但留着别删**（它是"怎么做的"的档案）。

```
你的项目/
└─ .team/                 ← 队伍的办公桌；公共记忆在 memory.md
   leader/  design/  dev/  test/  review/  retro/  hire/
      每个岗位一个文件夹：now.md（短期）· memory.md（长期）· <日期>/log.md（当天流水）
```

## 硬边界（结构性的，不是嘱咐）

- **评审和复盘只能写 `.team/` 下的东西**，而且没有命令行。
  落点按**真实路径**算：`.team/review/../../x.txt` 这种绕法也拦得住（设计和美工不在这条限制里 —— 她要跑渲染、要看输出）。
- **组员不许再招人**，并且**默认在后台干活** —— 派完组长就回来，你随时能跟她说话。
  ⚠️ 代价是关卡次序、"评审期间项目文件不许动"从结构强制降成了纪律。
- **评审前后项目文件必须逐字不变**，否则这次评审作废、重来。

## 装

> 🔴 **2026-09-28 换版：装法变了。** 旧的"拷进 `~/.dsh/.agent-presets/`"在 DSH 0.1.7 下
> **已经完全失效**（框架不再扫任何预设目录），症状是预设菜单里只剩出厂那四个。
> 现在这份预设是一个 **bundle**。

### 要什么

- **DSH 0.1.7 或更新**（旧版没有 bundle 机制，装了也不会出现）。
- 仓库放哪儿都行，但**放好之后就别搬**：补丁里有**两处写死了绝对路径**（注入器的
  `file:///…/inject.js` 与 `contentDir`），指的就是作者机器上的那个位置 ——
  **别人装在不同的目录，得先把这两处改成自己的路径**（跑一次下面那个生成器就行，见
  「自己改这份预设的人注意」）。改完再装。
- 装的时候宿主会调用 **pnpm**。它在 PATH 上找不到就会直接失败，报文是
  `'pnpm' is not recognized...`（`dsh plugin` 那条命令同病）。先确认 `pnpm --version` 有输出。
  ⚠️ 本机踩过一次：pnpm "装着但坏了"（下载被截断，`pnpm.exe` 只有正常体积的三分之一，
  Windows 报*不是本平台的有效应用程序*）—— 那种情况 `npm i -g pnpm` 重装即可。

### 三步

1. 打开 DSH 的 Web GUI → **插件**页 → **添加插件**。
2. 来源选**本地目录**，填**这个文件夹的绝对路径**，也就是
   `<你放仓库的地方>/presets/agenia`（例：`E:\Harness\presets\agenia`）。
3. 装。

宿主会把它登记成一个叫 `agenia-injector` 的 bundle，并且**用目录联接（junction）指回这个文件夹** ——
不是拷贝。所以之后 `git pull` 就是升级，**改 `.md` 存盘即生效**。

### 装完怎么知道成了

**新开一个会话**，**先看一眼模式菜单里选中的是不是「Agenia 模式」** ——
🔴 **新会话的默认可能跑在 `standard` 上**（2026-10-01 实测）：那时候 `.team/` 那套规矩、
五个岗位、写权限边界**一样都不在**，而**症状不是报错，是"她看起来很普通"**。
选错了就切过来，**切完按「开工」重走一遍**。

然后问她三件事：

| 问她 | 该看到的 |
| --- | --- |
| ① 你是谁，手底下有几个人 | 报得出自己的名字 + 五个固定岗位 |
| ② 让她派评审去改一个源码文件 | 评审**拒绝**，说自己只能写 `.team/` 下面 |
| ③ 说「开工」 | 她先报一句**自己跑在哪份预设上**，再去读 `.team/leader/now.md`，并报一句有没有 `前日复盘.md` |

三样都对，就是装好了。

⚠️ **装上了 ≠ 挂起来了。** 菜单里那条**带一条红色诊断**（设置 → Agent 预设 里写作「加载失败」）
就是没挂起来；那两处不一样，别把"菜单里看得见"当成"能用"。

### 不想装、或者要卸

- **卸**：插件页里把 `agenia-injector` 关掉或移除即可（移除只删 profile 里那条链接，**不会动这个文件夹**）。
- **不想让它跟着仓库走**（比如想让包管理器碰不到这个目录）：把
  [`presets/agenia/cordis.patch.yml`](presets/agenia/cordis.patch.yml) 的正文**整段**粘进
  `~/.dsh/profiles/<档位>/cordis.patch.yml` —— 两个文件是同一种方言，等效。⚠️ 那个文件是**热补丁层**，
  改它要**在 harness 关着的时候**做，否则正在跑的会话可能被一起拆掉。

### 自己改这份预设的人注意两件事

- **改 `agent.cordis.yml`（能力表）之后，必须跑一次生成器**：
  `<node> .tools/make-bundle-patch.mjs` —— `cordis.patch.yml` 是它的**派生物**，
  改完不跑，两份就对不上了（体检脚本有一条断言盯着）。
- ⚠️ **补丁里有两处写死的绝对路径**（注入器的 `file:///…/inject.js` 与 `contentDir`），
  生成器负责改写。**换机器 / 换目录，改生成器里那两行常量，再跑一次生成器。**

更细的装法、目录结构、怎么改人格与队伍，见 [`说明.md`](presets/agenia/说明.md)；
装法与坑的完整记录见 [`INSTALL.md`](INSTALL.md)。

进提示词的 markdown 是 **11 份**（人格 / 说话方式 / 带队方式 / 工序 / 六个岗位说明书）—— 改 `.md` **存盘即生效**，
改 `inject.js`（唯一的代码）**必须重启 harness**：不重启不生效，而且不报错。

细节在 [`INSTALL.md`](INSTALL.md)（装法 / 验证 / 坑）和 [`说明.md`](presets/agenia/说明.md)（怎么改 / 目录结构）· MIT，见 [`LICENSE`](LICENSE)。
