# dsh-preset-Agenia

**Agenia** 是给 DeepSeek Harness（DSH）用的一份 agent preset：**一个带班子的工程组长**。

选「Agenia 模式」和选「标准模式」，她能*做*的事**只会多不会少** —— 标准模式有的工具她
一样不少，另外多出一支固定编制的队伍和一道写权限边界。多出来的部分在下面全部列清了。

> **想把它装起来用？** **把一个文件夹拷进去就完事** —— 三步，见下面「安装」。
> 没有命令行，也没有要手写的配置文件。

## 她是谁

16 岁女高中生，现在是**这个组的组长**。干练、直接、有锋利感，emoji 和颜文字照用。

**该损就损，该卖乖就卖乖**，语气不用端着 —— 但**损的是事，不是人**。
她唯一不给面子的东西是：**糊弄**。口头禅是「**证据呢？**」——
这句话她对组员说，也对自己说。

> 怎么说话在 `persona.md` 里有**整节例子**：emoji 一张表、颜文字一张表、口癖一张表，
> 每个都写明什么时候用。**名字、年龄、脾气只住在这一份里** —— 改名只改它。

## 她的班子

六个人，六个时区，**从没见过面**。她们在一个青少年开源社区里认识，起因通常很随意：
有人手上有个做不完的东西，丢进群里，谁有空谁上。这一次的活儿是你的项目。

**她们从来不开会** —— 六个时区，任何"大家一起在线"的时间都是某个人凌晨三点。
所以这个组只有一种协作方式：**把该写的写下来**。谁做了什么、为什么这么做、留了什么坑，
全部进文档。

| --- | --- | --- | --- |

| **实现** | 佐西亚（Zofia） | 波兰 · 数学竞赛出身 | 每票活 |

**她兼产品。** 需求方向上的事你直接跟她谈；**产品与体验的口径她定、也由她落档**（**默认全在 `.team/` 里**；只有"项目级、你也要照着做"的决定才追加进仓库里本来就有的 `doc/DESIGN.md`），拿不准才来问你。（2026-09-24 起）

## 她的办公桌：`.team/`

**你把一个工作区交给她，她和队员的所有痕迹都落在项目里的 `.team/`。**

```
你的项目/
├─ （你的代码……）
└─ .team/                  ← 她建的；**留着**（那是"怎么做的"的档案）
   ├─ leader/              一个岗位一个文件夹，结构都一样
   │  ├─ now.md            ← 短期：手头这件事（每天开工重写，不是追加）
   │  ├─ memory.md         ← 长期：这个项目里一直成立的事实（上限 2000 字）
   │  └─ 2026-09-20/       ← 当天的工作抽屉
   │     └─ log.md         这一天的流水（过完这天就不再动）
   ├─ design/ dev/ test/ review/ retro/
   └─ hire/                临时外聘
      └─ 2026-09-20/       一天一个抽屉，干完就走
```

**日期文件夹是当天的工作抽屉。** 干完一天，抽屉合上，第二天新开一个。

**上岗四步，收工两步**（这是唯一要背下来的纪律）：

```
上岗：读自己的 now.md 全文 → 读自己的 memory.md 全文
      → 读抽屉里 log.md 的尾部（"上次 / 昨天发生了什么"）→ 接任务
收工：追加今天的 log.md → 重写 now.md
```

> **`log.md` 永远不整篇读。** 实测：一个角色只干两天，日志就到了 **136 KB**（三万多 token）；
> 每上岗全文读一遍，就是每上一岗烧一次，而且随天数线性涨。

**建议把 `.team/` 加进 `.gitignore`。** 🔴 **但别删它**（2026-09-24 老板：「没人会删的」）——
"项目不该有任何感觉"靠 `.gitignore` 就够了；`.team/` 是**「怎么做的」的档案**，交活之后价值最大。
开工第一步她会看一眼 `.gitignore` 里有没有这一行，没有会提醒你 —— 但
**她不替你改 git，也不 commit / push**，那是你的决定。

## 五道关

| 关 | 谁 | 交出什么 | 什么算过 |
| --- | --- | --- | --- |
| **1 定形** | 组长 | 问题 · 目标 · 改动范围 · **不做清单** · 验收口径（写进她的 `now.md`） | 验收口径能被验证 |
| **2 契约与测试** | 测试 | 技术契约 + 测试用例集 | **功能还没做时，测试必须是红的** |
| **3 实现** | 实现 | 代码 + 跑过的检查输出 | 检查全绿；没有超范围 |
| **4 独立评审** | 评审 | 通过 / 有条件通过 / 打回 | **不是作者**，且**没看过实现过程** |
| **5 验收** | 组长 | 逐条核对的记录（写进她当天的 `log.md`） | 逐条核对第 1 关 |

**不是所有事都走全套。** 分诊是组长的第一职责：一句话能答的自己答；小改动自己干；
新功能、改行为、碰架构才叫人。**"工具密集型的活，多人协作是净亏损"** —— 这条写进了她的手册。

## 硬边界（结构性的，不是嘱咐）

- **评审和流程只能写项目里 `.team/` 下的东西。** 往项目文件上写，系统当场拦下：
  `你的岗位（review）只能写项目里 .team/ 下面的东西。`
  落点按**真实路径**算 —— `.team/review/../../x.txt` 这种绕法是拦得住的。
- **这两个岗位也没有 shell。** 一条通用命令行就是一条通用写入通道，留着它这道边界就是纸的。
  所以"每天看一眼今天的复盘在不在"这件事**只能组长干** —— 但理由不是别人没命令行：
  **设计 / 实现 / 测试三个岗位都有命令行**（要跑构建、要渲染、要看输出）。理由是这条纪律
  本身是她的"开工第一步"，派出去就等于降成嘱托。
- **只放"做判断"的岗位。** 评审和复盘的产出必须是意见、不能是改动，限制和工作正好对得上。
  ⚠️ **设计和美工不在名单里**：她的产出本来就是文件（设计稿 / HTML / 渲染 PDF），
  这些活要跑命令行。要命令行就不能要写边界，两样只能挑一样。
- **流程每天缩别人的 `memory.md`，看着像越权，其实没越** —— 别人的 `memory.md` 也在
  `.team/` 里面。这道边界本来就是"只能写 `.team/`"，正好够她办事，**没为它开后门**。
- **组员不许再招人**（`maxDepth: 1`，结构上做不到）。
- **组员默认在后台干活**：派完组长就回来了 —— 所以你**随时能跟她说话**，不必等某个组员干完。
  ⚠️ 代价说清楚：改成后台之后，"关卡次序"和"评审期间项目文件不许动"这两条**从结构强制
  降成了纪律**（原来靠"她被那个调用卡住"物理撑着）。替代措施写在 `leader.md`「派工」那一节：
  跨关不许并、派评审前后各量一次哈希。
- **评审前后项目文件必须逐字不变**，否则这次评审作废、重来。

## 文件

被注入提示词的有**九份**，按受众分两套：

| 文件 | 管什么 | 组长 | 组员 |
| --- | --- | --- | --- |
| `persona.md` | 她是谁 / 怎么说话 | ✅ | ❌ |
| `leader.md` | 这支队伍 + 她怎么带队 + 每天开工第一步 | ✅ | ❌ |
| `work-guidelines.md` | 干活的次序 · 工作位置（`.team/`）· 九条工作原则 | ✅ | ✅ |
| `team/<角色>.md` ×6 | 岗位说明书（含 `hire.md`） | 只在名册里露一行 | **只拿到自己那份** |
| ⚠️ **算出来的两段**（不是文件） | `agenia:roster` 名册 · `agenia:board` 进度板 | ✅ **只有组长** | ❌ |

**每一份都是 markdown，存盘即生效** —— 正在跑的会话下一个步骤就变。

**注入顺序是有意的**，写在 `agent.cordis.yml` 里：

```yaml
leaderOrder:            # 组长收到的，从上到下就是这个顺序
  - leader
  - work-guidelines
  - roster              # 算出来的：队伍一览
  - board               # 算出来的：这一票干到哪了
  - persona             # ★ 故意放最后

memberOrder:            # 组员收到的
  - work-guidelines
  - charter             # 他自己那份岗位说明书（算出来的）
```

**`persona` 故意排在最后** —— 越靠后离请求末尾越近，权重越高。"她是组长"这件事，
比其他任何一条都更需要"刚刚读过"。

> ### ⚠ 改了注入器的代码（`presets/agenia/inject.js`）必须重启 harness
>
> 那个文件是**代码**，ESM 按 URL 缓存，改它不会自动重新加载。而且**"导入失败"也会
> 被缓存** —— 它曾一度处于语法错误状态，导致之后无论怎么修都一直复用坏掉的实例，
> 注入**静默消失**（挂载、行状态全都正常）。
>
> **唯一管用的办法是重启 harness。** 行名写的是预设相对路径 `./inject.js` ——
> 路径里既没有版本号、也没有查询串，所以改 `package.json` 的 `version` 换不出新 URL。
> 写完先 `node --check presets/agenia/inject.js`，别让它带着语法错待着。
>
> **那九份 .md 都不受影响** —— 它们每轮从磁盘读，改完存盘照旧即时生效。

## 改人格 / 改守则 / 改工序

**直接改那几个 .md 就行，保存即可生效。**

> ⚠️ **要改"她正在读的那一份"。** 按下面「安装」拷文件夹装的，她在读的是
> `%USERPROFILE%\.dsh\.agent-presets\agenia\` 里的那一份 —— 改仓库里这份不会影响她。

- **改她的性格和说话方式** —— 改 `persona.md`。整个仓库没有第二处。
- **改她怎么带队、每天开工第一步** —— 改 `leader.md`。
- **改工作位置 / 次序 / 原则** —— 改 `work-guidelines.md`。
  它**全组都读**，所以只往里面写"组员也需要知道"的东西。
- **改队员** —— 改 `team/<角色>.md`。名字和脾气都在里面，**改名只改那一份**。
- **加减岗位** —— 两步：`team/` 里加一个 `.md` + `agent.cordis.yml` 里加一行。
  **两处必须一起改**：只加说明书、没加能力行，整个队伍启动时一起挂。
  体检脚本里有一条断言专门盯这个对应关系。
  ⚠️ 那一行的 `toolName` 必须写成 **`team_<岗位名>`**（岗位名 = 你刚放进去那个 `.md` 的文件名）
  —— 进度板按这个约定认人，写成别的形状不会报错，只是那个岗位不出现在板子上。

四件别做的事：

- **不要给 `agent.cordis.yml` 里的 `persona` 行加 `complete: true`。** 那会让它变成
  唯一的提示词段落，项目自己的 `AGENTS.md` 就再也读不进来了。
- **不要在任何一份 .md 里写半截的 `{{`。** 提示词里的 `{{...}}` 是变量引用，
  写错会直接抛错。
- **不要把项目专属的规矩写进这些文件。** 它们是**全局**的，会跟着预设进每一个项目；
  项目自己的约定归项目自己的 `AGENTS.md`。
- **不要把队员的名字写进 `agent.cordis.yml`。** 名字只住在 `team/<角色>.md` 里。
  （组员行里那个 `【组员:<role>】` 标记不算 —— 那是机器要读的锚点，不含名字、不含性格。）

## 和能力的关系（这条规矩 2026-09-16 改过）

**以前**写的是「除两行外全部照抄 `standard`，意图是永远一模一样」。
**现在不是了** —— 团队那六项是刻意加的能力。规矩改成：

> **`onlyInStandard` 必须为空；`onlyInAgenia` 必须正好是这六项**：
> `persona-injector` · 五条 `team-*` 行（另加 `subagent` 行上的一个 `persona` 键）。
> ⚠️ `persona` 那一行**不算差异** —— 出厂 `standard` 自己就有它，它在这里的作用只是遮蔽出厂人格。

有工具可验，不用肉眼比对 —— `.tools/check-notes.mjs` 的 `composition` 那一族就是它。
**2026-09-20 实测**（换到新版预设之后仍然成立）：`standard` **31** 行 · `agenia` **37** 行 ·
`onlyInStandard` **空** · `onlyInAgenia` **6 项**
（`persona-injector` + `team-design` / `team-dev` / `team-test` / `team-review` / `team-retro`）。

## 目录结构

```
presets/
└─ agenia/                     ← 装的时候拷的就是这一层
   ├─ agent.cordis.yml        # 组合本体：能力照抄 standard，另加 6 项
   ├─ package.json            # name 和 version 都必须有
   ├─ inject.js               # ★ 唯一的代码：注入（快照 + 尾巴提醒）+ 写权限边界
   ├─ 说明.md                 #   给维护的人看的（不进提示词）
   │
   ├─ persona.md              # ★ 她是谁（身份 + 基本说明）   （只有组长读）
   ├─ style.md                # ★ 她怎么说话（情绪化表达 / emoji / 颜文字 / 口癖 / 标点）
   │                          #   同一份走两条路：会话开头 + 每 N 步贴到最末尾
   ├─ leader.md               # ★ 这支队伍 + 她怎么带队     （只有组长读）
   ├─ work-guidelines.md      # ★ 工作位置 + 次序 + 原则    （全组都读）
   │
   ├─ team/                   # 一个岗位一个文件
   │  ├─ design.md            #   设计与美工
   │  ├─ dev.md  test.md  review.md  retro.md
   │  └─ hire.md              #   临时外聘
   └─ preset.yml              #   预设菜单里的名字和说明
README.md  INSTALL.md  LICENSE  .gitignore  .gitattributes
```

**每个子目录的名字就是 preset id**：`presets/agenia/` → id 是 `agenia`。
id 必须匹配 `[a-z0-9][a-z0-9-]*` —— 所以那个文件夹拷过去之后**不能带"副本"两个字**。

`api.txt` 和这些文件放在一起，但**永远不会进版本库** —— `.gitignore` 挡着它。
（维护者本机才有这个文件；**运行 Agenia 不需要它**。）

## 安装（第一次装，看这一节就够）

### 三步

**1. 把 `presets\agenia` 这个文件夹，整个拷进 `%USERPROFILE%\.dsh\.agent-presets\`。**
（在资源管理器地址栏里粘 `%USERPROFILE%\.dsh\.agent-presets` 回车就到了；没有这个文件夹
就自己建一个，**名字一个字都不能差**。）

**2. 不用关 DSH。** 拷完就完事了 —— 正在跑的这个 harness 不用停、也不用重启。

**3. 新开一个会话** → 点输入框上方写着「标准模式」的那一格 → 选「**Agenia 模式**」。

**就这三步。** 不用装任何东西，也没有要手写的配置文件 —— 那个插件文件（`inject.js`）
就在 `agenia` 文件夹里，**跟着它一起走**。`~/.dsh/.agent-presets/` 是 DSH 默认就会去找
预设的地方，不需要谁去登记。

> **为什么不用重启**：DSH **每次现扫**那个目录 —— 实测（本机 Windows，2026-09-20）：
> 同一个 harness 进程、**没重启**，运行中往用户根写进去一份新预设，**26 秒后**名单里
> 就有它了（5 条 → 6 条）。
>
> **万一菜单里一时没出现它：重启一次 DSH**（关掉，再开）就好了 —— 那是**兜底**，
> 不是装的时候必须先做的事。

**怎么知道成了** —— 问她三件事，一件对一样：

| 问 | 应该看到 |
| --- | --- |
| 「你是谁，手底下有几个人」 | 她自称 16 岁的组长，报得出名字和五个岗位 → **注入通了** |
| 让她派评审去改一个源码文件 | 评审拒绝，说只能写 `.team/` → **写边界生效了** |
| 说「开工」 | 她先读 `.team/leader/now.md`，并报一句 `.team/retro/<今天>/` 里有没有 `每日复盘.md` → **工作位置那套规矩进去了** |

> 装的过程中卡住了、或者想看"为什么这么装"，见 [`INSTALL.md`](INSTALL.md)。
> 想知道每个文件为什么长这样，见 [`presets/agenia/说明.md`](presets/agenia/说明.md)。

### 菜单里没有「Agenia 模式」？三种可能，而且都不报错

| 长这样 | 真实原因 |
| --- | --- |
| `agenia` 文件夹里还套着一层 `agenia\` | 你拷的是它的**上一层**。要的是"进去第一眼就是 `agent.cordis.yml`"的那个文件夹 |
| 名字成了 `agenia - 副本` / `agenia (1)` | 文件夹名只允许小写字母、数字和短横。名字不合法 ⇒ **DSH 直接跳过，一句提示都没有** |
| 文件夹图标上带着小箭头（快捷方式 / 目录联接） | 联接这条路**不通**，见下面「Windows 坑」。必须是**真的拷进去** |

改完**新开一个会话**再看一眼那一格；**还没有就重启一次 DSH** —— 那是兜底。

### 不想要了

把 `.agent-presets\agenia` 这个文件夹删掉，**就完了** —— 它没往别的地方装过任何东西。
（想让菜单里立刻没有它，重启一次 —— 跟装的时候一样，那是兜底。）

## 一个值得记下来的 Windows 坑

在 `~/.dsh/.agent-presets/agenia` 建一个指向本仓库的**目录联接（junction）**
是**不行的**，而且静默失败：

```
node: dirent.isDirectory=false, dirent.isSymbolicLink=true
```

Node 会把 Windows 的目录联接报成符号链接、而不是目录，而名册的扫描器会跳过非目录。
资源管理器、`PowerShell` 和 `cmd` 都能正常解析这个联接，所以它看起来装上了，
实际上 DSH 完全看不见。**所以装的时候是"拷一份进去"，不是建联接。**
