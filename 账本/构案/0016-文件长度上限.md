## ② 决定

**两类划分 + 分档上限。** 「历史」不设上限；「现状」按类给上限：

| 现状类 | 上限（行） |
| --- | --- |
| 代码 `.mjs` / `.js`（`presets/**`） | **800** |
| 说明书 / 作业书 | **300** |
| 契约 / 构案（`CONTRACT.md`、`账本/构案/*.md`） | **250** |
| 配置 `.yml`（手写的） | **700** |
| `now.md` | **80** |

- **历史类不设上限**：`log.md`、报告、会话包、`_archive/`、`.team/**/cards/`、证据目录。
- 🔴 **生成物与数据不算「现状文档」**：`cordis.patch.yml`（由 `agent.cordis.yml` 派生）、`账本/缺陷/*.json`（事件流）、
  `INDEX.md`（派生页）**不进这条表** —— 否则「拆」会拆到不该拆的东西上（派生物拆了也白拆）。
- **超限不是一个数，是一个问题**：报文必须逼出三种成因之一 —— ①历史性内容写进现状 ②该拆 ③注释 / 废话太多。
  **「拆」不是默认答案**：先问「这份文件该不该存在」（删除优先）。
- **存量与增量分开**：这条只对**新增 / 改动**的文件生效；现存超限的按票分批拆（今天超的 11 份挂票，不今天硬拆）。

## ③ 复用什么

`check-notes.mjs` 已有的文件遍历与「具名白名单」习惯；上限表放**一处**（工具里），别在文档里抄第二份。
🔴 **改数字 = 本构案 §② + `.tools/check-notes.mjs` 的 `FILE_CAP_TABLE` 同批** —— 体检里有一条判据逐值对账
（`0016 §②` 与工具表相等），只改一处会当场红；`CONTRACT.md` §17 只指表、不抄数字与适用面。
存量的锚是**票**（`账本/缺陷/` 里 tag `file-length` + `deferred` 的票，`evidence[].note` 以「N 行」开头 =
冻结点），不是 `HEAD` —— 一次 commit 洗不成存量，存量只许缩。

## ④ 不复用什么

- 否「一刀切一个数」：说明书 300 与代码 800 是两件事，一刀切会逼人在注释上凑数。
- 否「按字节」：行数才是人读的单位（字节受语言影响）。
- 否「超限就红一片」：第一天红 11 份 = 恒红 = 教人忽略它（`mig-rules-11`）。

## ⑤ 新增什么

- `check-notes.mjs` 一族判据：按类判行数；**读数带「这一类今天几份 / 超几份 / 是谁」**；只对新增（或 `--all` 时对存量）判红。
- 上限表一处（`check-notes.mjs` 里的常量 + 注释写明来历 = 本构案）。
- 11 份存量超限各自的拆票（见 ① 的表）。

## ⑥ 公共化时点

随预设分发：别的工区升级后按同一张表判；历史类不设上限 ⇒ **不会**因为别人的日志长而红。
